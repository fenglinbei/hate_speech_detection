# Hate Speech Detection

English | [Chinese](README_zh.md)

This repository contains data construction, fine-tuning, inference, and evaluation utilities for structured hate speech detection. The main pipeline builds quadruple-style prompts, fine-tunes an instruction model, serves the checkpoint with vLLM, and evaluates runner outputs with `LLMmetrics`.

## Repository Layout

- `data/build_data.py`: builds `train.jsonl`, `val.jsonl`, and runner-ready `test.json` from normalized quadruple data.
- `data/cold_adapter.py`: converts COLD-style raw files into the project standard format.
- `data/exp_data/*/config.json`: data construction configs.
- `finetune/train.py`: fine-tuning entry point.
- `finetune/config/*/*.json`: fine-tuning configs.
- `runner/run.py`: LLM inference and metric computation entry point.
- `runner/config/*/*.json`: runner configs.
- `scripts/exps/run_all.sh`: one-click loop for the k-ablation style pipeline.
- `scripts/exps/run_one_exp.sh`: one-click runner for an `exp_*` directory generated by `expctl.py`.
- `scripts/exps/expctl.py`: generates self-contained experiment directories from a JSON spec.

## Data Format

The normalized training and test data use:

```json
{
  "id": "sample_id",
  "content": "input text",
  "quadruples": [
    {
      "target": "NULL",
      "argument": "input text or evidence span",
      "targeted_group": "Racism",
      "hateful": "hate"
    }
  ]
}
```

`data/build_data.py` turns this format into:

- `train.jsonl`
- `val.jsonl`
- `test.json` with `id`, `content`, `gt_quadruples`, and `messages_list`

## Quick Start: Main Experiment

The main experiment is the k=10 class-quota setting:

- Build config: `data/exp_data/k_ablation/k10/config.json`
- Train config: `finetune/config/k_ablation/k10.json`
- Runner config: `runner/config/k_ablation/k10.json`
- Demonstrations: `srag_top_k = 10`
- Selection: `stratified = true`, `weights = null`, which uses the default class quota in `rag/core.py`

### Prerequisites

Run from the repository root. The one-click scripts are Bash scripts, so use Linux, WSL, Git Bash, or another Bash-compatible shell.

Required runtime tools:

- Python environment with the project dependencies installed, including `torch`, `transformers`, `sentence-transformers`, `scikit-learn`, `numpy`, `tqdm`, `loguru`, and `vllm`
- `curl`
- `nvidia-smi`
- `jq` for `scripts/exps/run_all.sh`

Required local assets:

- Base LLM: `models/base/Qwen2.5-7B-Instruct`
- Retrieval model: `models/base/bge-large-zh-v1.5`
- Standard dataset: `data/full/std/train.json` and `data/full/std/test.json`
- Lexicon data: `data/lexicon/annotated_lexicon.json`

### Run k=10 End to End

In Bash:

```bash
K_START=10 K_END=10 MODE=full \
TRAIN_CUDA_VISIBLE_DEVICES=0,1,2,3 \
VLLM_CUDA_VISIBLE_DEVICES=0,1,2,3 \
TENSOR_PARALLEL_SIZE=4 \
bash scripts/exps/run_all.sh
```

In PowerShell, set environment variables first and then call Bash:

```powershell
$env:K_START="10"
$env:K_END="10"
$env:MODE="full"
$env:TRAIN_CUDA_VISIBLE_DEVICES="0,1,2,3"
$env:VLLM_CUDA_VISIBLE_DEVICES="0,1,2,3"
$env:TENSOR_PARALLEL_SIZE="4"
bash scripts/exps/run_all.sh
```

This performs:

1. Data construction with `data/build_data.py --config data/exp_data/k_ablation/k10/config.json`
2. Fine-tuning with `finetune/train.py --config finetune/config/k_ablation/k10.json`
3. vLLM startup on port `35010`
4. Runner evaluation with `runner/run.py --config runner/config/k_ablation/k10.json`

### Run by Stage

Build data only:

```bash
K_START=10 K_END=10 MODE=data bash scripts/exps/run_all.sh
```

Build data and train, but do not run inference:

```bash
K_START=10 K_END=10 MODE=train bash scripts/exps/run_all.sh
```

Run the full pipeline:

```bash
K_START=10 K_END=10 MODE=full bash scripts/exps/run_all.sh
```

`run_all.sh` skips existing artifacts by default:

- `SKIP_BUILD_IF_EXISTS=1`
- `SKIP_TRAIN_IF_EXISTS=1`
- `SKIP_RUN_IF_EXISTS=1`

Set any of them to `0` to force rerunning that stage.

### Main Outputs

For k=10, the expected outputs are:

- Built data: `data/exp_data/k_ablation/k10/train.jsonl`, `val.jsonl`, `test.json`
- Checkpoints: `models/exps/k_ablation/k10/checkpoint-*`
- Runner logs: `logs/k_ablation/k10_*.log`
- Runner outputs: `runner/output/k_ablation/k10_s<seed>.json`
- Multi-seed summary: `runner/output/k_ablation/k10_multi_seed.json`

The runner config uses these seeds by default:

```text
42, 4242, 424242, 42424242, 4242424242
```

## Regenerate k-Ablation Configs

If the k-ablation configs are missing, regenerate them from the k=1 templates:

```bash
K_START=2 K_END=20 BASE_K=1 bash scripts/exps/make_config.sh
```

For only k=10:

```bash
K_START=10 K_END=10 BASE_K=1 bash scripts/exps/make_config.sh
```

`make_config.sh` writes:

- `data/exp_data/k_ablation/k{k}/config.json`
- `finetune/config/k_ablation/k{k}.json`
- `runner/config/k_ablation/k{k}.json`
- `runner/start_comand/k_ablation/k{k}.sh`

## Self-Contained Experiment Directories

`scripts/exps/expctl.py` can generate independent `exp_*` directories from a spec:

```bash
python scripts/exps/expctl.py gen --spec path/to/spec.json
```

Each generated experiment directory contains:

- `build_config.json`
- `train_config.json`
- `runner_config.json`
- `manifest.json`
- local `data/`, `model/`, `runner_output/`, `logs/`, `progress/`, `prompts/`, and `cache/` folders

Run one generated experiment:

```bash
MODE=full bash scripts/exps/run_one_exp.sh exps/some_project/exp_xxxxxxxxxx
```

Run all generated experiments under a root:

```bash
MODE=full bash scripts/exps/run_all_exps.sh exps/some_project
```

`run_one_exp.sh` also supports `MODE=infer` when a checkpoint is already available.

## COLD Fixed-Split Conversion

If raw COLD files are already downloaded under `data/cold/raw` as `train.csv`, `dev.csv` or `val.csv`, and `test.csv`, convert them without reshuffling:

```bash
python data/cold_adapter.py --raw-dir data/cold/raw --output-dir data/cold/std
```

This writes:

- `data/cold/std/train.json`
- `data/cold/std/val.json`
- `data/cold/std/test.json`

Single-file conversion is still available:

```bash
python data/cold_adapter.py --input path/to/cold.csv --output-dir data/cold/std
```

Single-file mode may split the input if no split column is present. Prefer `--raw-dir` when fixed train/dev/test files exist.

## Runner-Only Evaluation

If a vLLM/OpenAI-compatible endpoint is already running, call the runner directly:

```bash
python runner/run.py --config runner/config/k_ablation/k10.json
```

Make sure `runner/config/k_ablation/k10.json` points to the correct:

- `model.params.api_base`
- `tester.test_data_file`
- `tester.output_dir`

## Paired Bootstrap

Bootstrap utilities live under `scripts/paired_bootstrap/`.

Single-system confidence interval:

```bash
python scripts/paired_bootstrap/paired_bootstrap_llm.py \
  --system-a runner/output/k_ablation/k10_s42.json \
  --n-bootstrap 10000 \
  --seed 42 \
  --output output/paired_bootstrap/k10_s42.json
```

Paired comparison:

```bash
python scripts/paired_bootstrap/paired_bootstrap_llm.py \
  --system-a path/to/system_a.json \
  --system-b runner/output/k_ablation/k10_s42.json \
  --metric f1_avg,f1_target,f1_hate \
  --n-bootstrap 10000 \
  --output output/paired_bootstrap/system_a_vs_k10.json
```

Inputs should be runner output JSON files with a top-level `results` list.

## Common Troubleshooting

- Missing `tqdm`, `transformers`, or `sentence_transformers`: install the project Python dependencies in the active environment.
- `jq not found`: install `jq`, or use `scripts/exps/run_one_exp.sh`, which patches JSON via Python.
- vLLM does not become ready: inspect `logs/k_ablation/k10_vllm_port35010.log`.
- No checkpoint found: run `MODE=train` or `MODE=full`, or point `MODEL_CKPT_OVERRIDE` to an existing checkpoint when using `run_one_exp.sh`.
- Wrong port: k=10 uses `PORT_BASE + k`, so the default is `35010`.
