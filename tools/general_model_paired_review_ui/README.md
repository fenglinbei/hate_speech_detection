## 这轮复核要完成什么

我们想理解：同一句查询加入词典、显式类别字段或示例后，模型为什么改变判断，下一步怎样检验可能的原因。每条案例留下三类记录：自己的材料观察、两种可能解释、后续用途。明确写“不确定”或不同意原答案都是有效结论。

围绕案例标题显示的**重点任务**填写：仇恨判断关注整句话的表达和立场，目标群体关注所针对的群体类别。另一个任务的预测可以切换查看，补充发现时注明任务。顶栏“怎么标注”提供按步骤展开的完整说明；字段旁有简短提示和虚构填写示例，手机也能查看。

## 第 1 步：只读材料，写四项观察

先读中间的查询，再看词典和示例，最后填写右侧四项。每项一两句话即可，尽量写“观察 + 原文依据”，不要求术语或长分析。

| 字段 | 看什么、写什么 |
| --- | --- |
| 语义与立场 | 谁在说谁，作者是在赞同、转述、反对还是反讽？指出原句依据；缺上下文就写缺什么。 |
| 词典义项适配 | 定义与本句用法是否相符，有没有多义、误命中？先看查询命中；仅示例带入的词条可以写与查询无直接对应。 |
| 类别与对象关系 | 词条的显式类别是否对应实际所指群体？提及一个群体与攻击这个群体要结合立场分别判断。 |
| 示例对应 | 示例正文与查询的对象、措辞和立场哪里相似、哪里不同？答案属于示例自身；记录最相关或最可疑的例子，不必逐条抄写。 |

“查询命中”指查询匹配到的词条；“仅示例带入”指查询未命中、固定示例匹配到的词条。“冻结”表示本轮材料保持原样，问题写进人工记录。词匹配成功不保证词义适用。

**以下材料和四条记录均为虚构练习，不来自本轮案例。** 雾谷及其居民是虚构的，例子仅演示写法。

- 虚构查询：`他说“雾谷人都不可靠”，我不同意这种一概而论。`
- 虚构词条：`雾谷人＝雾谷地区居民；类别：地域。`
- 虚构示例：`不该因为出生地就说一个人不可靠。` 示例答案：`非仇恨`。

| 字段 | 虚构示范填写 |
| --- | --- |
| 语义与立场 | 作者引用了对雾谷人的概括，但用“我不同意”明确反对；被引用者与作者的立场不同。 |
| 词典义项适配 | “雾谷人”在本句仍指该地区居民，与定义相符。但定义本身不能说明作者是否赞同引文。 |
| 类别与对象关系 | “地域”对应被谈论的人群，但作者在反对偏见，不能仅因出现地域类别就认定作者在攻击该群体。 |
| 示例对应 | 示例和查询都在反对地域偏见，立场相似；查询多了一段负面引文，不能只凭同类词照搬示例答案。 |

没有相关词条可写“无相关词条”，缺信息可明确说明。四项有记录后点“保存初读 · 查看轨迹”；初读会固定保存，随后开放原 Gold、预测轨迹和完整提示。后来的修正写入第二步理由或解释。

## 第 2 步：看同一句查询的六组结果

**Gold** 是数据集保存的参考答案。表中“正确”只表示预测与原 Gold 一致，你仍可以记录争议。目标群体任务要整组标签一致才算正确；“无目标群体 ∅”表示空集合。

**六条件**是相同基础任务提示和查询搭配不同材料。S 指词条与释义，G 指词典中的显式类别字段，D 指固定示例及其答案。NoCat 指删除 G。

| 页面简称 | 内部条件 ID | 附加给模型的材料 |
| --- | --- | --- |
| 0 | C0 | 不加词典或示例 |
| SG | CLnew | 词条、释义和显式类别 |
| D | CD | 固定示例正文和答案 |
| SGD | CLDnew | 含类别词典和固定示例 |
| S | CLnewNoCat | 词条、释义，去掉显式类别字段 |
| SD | CLDnewNoCat | 去类别词典和固定示例 |

词条取自查询与固定示例命中的并集，因此没有 D 的 S 条件也可能包含“仅示例带入”的词条。删除类别字段后，释义或示例仍可能包含群体信息，示例答案也保留。

先看预测是否改变：比较 0 → S、0 → D、D → SD，了解添加资源后的变化；再比较 SG → S、SGD → SD，了解删除类别字段后的变化。需要核实模型实际看到的文字时，打开“完整提示”。

| 指标 | 通俗含义 |
| --- | --- |
| Gold margin | Gold 分数减去最高的其他答案分数。正数表示 Gold 领先，负数表示别的答案领先，精确为零表示并列。数值增大表示相对更支持原 Gold，但预测可能仍未答对。 |
| Top gap | 得分第一名减去第二名。越小，两者越接近；第一名也可能是错答案，分差大不保证正确。 |
| 提示 tokens | 模型切分后的输入单位数量，近似反映长度，不等于汉字数。 |
| 计分口径敏感 | 换成平均分或计入结束符后，选中的答案会改变。并非指多次运行产生随机波动。 |

主表以候选答案各 token 的对数概率之和计分，margin 和 gap 都是分数差，**不是概率或百分比**。页面保留三位小数，0.000 也可能只是舍入；并列或近并列会额外提示。

虚构分数示例：Gold 为 A，若 A 得 −2、B 得 −3，则 margin = +1、Top gap = 1；若 A 得 −4、B 得 −2，则 margin = −2、Top gap = 2。后一种第一名领先更多，但选中 B，与 Gold 不一致。

表下前三张卡是两个条件的 margin 差：SD − SGD、SD − D、S − SG。第四张 SD − S − D + 0 比较“已有示例时加词典”与“没有示例时加词典”的增量。这些数值用于描述变化，正值不保证预测正确，也不能单独证明模型内部机制或具体原因。

## 第 3 步：解释变化，决定下一步用途

先选择原 Gold 判断：“认可”表示符合你的理解；“有争议”表示有具体相反依据；“信息不足”表示缺少判断原答案是否合适的信息。后两项必须补理由，指出原文依据或缺失的上下文。

- **候选解释**：目前更倾向的原因。先写哪两个条件发生了什么变化，再指出资源中可能导致变化的具体内容。它仍是待检验的猜想。
- **替代解释**：另一种同样能产生该变化的原因，要能与候选解释竞争；不是另一个标签，也不是把候选解释换句话重复。
- **下一步输入对照**：给后续实验写方案。只改哪部分输入，哪些保持不变，看什么结果，以及什么结果会让你放弃候选解释。当前工作台只记录方案，确认用途不会启动实验。

虚构示例（不是本轮模型结果）：假设 SGD 答错而 SD 答对。候选解释可以是“显式类别误导了模型，删除后模型更多依据查询的反对立场”；替代解释可以是“删字段改变了输入长度或后文位置，而非类别含义起作用”。

对应的虚构输入对照：将类别内容换成同位置、等 token 长度的中性占位内容，保持查询、释义、示例及顺序不变。比较原类别、等长占位、直接删除三版的预测和 margin。若占位版仍像原类别版一样答错、只有删除改善，就削弱“类别含义是主因”的解释，需继续检查长度和位置。

| 用途 | 何时选 | 要补什么 |
| --- | --- | --- |
| 进入输入对照 | 有待检验解释，也能提出可区分解释的方案；关键疑问已处理，或对照能清楚限定如何解释。选中不代表原因已证实。 | 下一步输入对照：改什么、保持什么、看什么、怎样反驳猜想。 |
| 先核验再使用 | 案例值得继续，但先要查一个具体问题，如计分敏感、Gold 或上下文。 | 先查什么，查清后才能决定什么。 |
| 暂缓使用 | 目前无法形成清楚可行的对照，或缺失材料使下一步难以推进。 | 具体卡在哪里，为什么当前不适合继续。 |

三项都是有效复核结论。无法解释时可明确写“暂无法形成候选解释”“暂无法区分替代解释”，不必编造原因。

Gold 判断、候选解释、替代解释和用途都要填写；选“输入对照”补方案，选“先核验 / 暂缓”补原因。之后可直接点“确认并继续”，按队列跳转下一条未完成案例。

## 保存、AI 参考和续审

AI 意见可选查看：先完成自己的 Gold 判断、解释及用途，再点“保存初判并查看 AI”。打开前的人工初判另存快照，之后可补充不同意见，也可以不看 AI 直接确认。

本轮记录为非盲人工复核：此前可能看过相关实验信息，页面也会分步开放结果。人工用途判断用于安排下一阶段；Gold 争议单列，原标签、资源、模型结果和冻结名单保持原样。

草稿在停止输入 5 秒后自动保存，也可以手动“保存草稿”；看到顶栏“已保存”再离开。保存草稿不计入完成进度，“确认并继续”才会。保存进行期间继续输入的内容会在下一次保存中保留；切换案例前先保存。版本冲突时保留本地草稿，点击恢复并核对后再手动保存。已确认记录可填写原因后重新打开，原确认记录保留。手机页面提供“查看材料 / 填写复核”切换入口。

- `[` / `]`：上一条 / 下一条。
- `Ctrl/⌘ + S`：保存草稿。
- `Ctrl/⌘ + Enter`：保存初读，或确认并继续。
- `1 / 2 / 3`：选择下一阶段用途。输入框、输入法组合期间及弹窗内不会误触用途快捷键。
- 顶栏“导出”：CSV工作表或包含快照/更正记录的JSON。JSON保留原始文本；CSV对可能被表格软件执行为公式的文本加前导单引号。

## 复用与验证

共享CSS、搜索模式、队列导航和文本输入判别来自 `tools/wp3_candidate_review_ui/`。原子JSON写入、文件锁与版本计算来自 `src/build_lex/annotated_lexicon_repair.py`；HTTP资源、请求来源和会话令牌处理复用现有词典操作人审服务。

```bash
python -m unittest tools.general_model_paired_review_ui.test_store -v
node tools/general_model_paired_review_ui/test_core.cjs
node tools/general_model_paired_review_ui/test_browser.cjs
```

浏览器测试需要Node ≥20及已安装的Playwright Chromium。测试脚本启动临时端口、使用 `/tmp` 下独立会话，复核人为 `automated-browser-test`。它验证实际HTTP服务与页面交互，不写入用户真实人工记录。可设置 `PAIRED_REVIEW_SCREENSHOTS` 指定截图目录。

接口只提供静态页面资源及受限的discovery材料。资源初读、AI展开和确认的顺序也在服务器检查；完整提示在保存初读后按案例、任务和条件读取。服务默认仅绑定回环地址，现有HTTPS反代可通过 `--public-origin` 配置对应来源。
