    判断口径 · 操作指引
    先解释用法，再审核类别、变体与条件
    
        
    
          
    第一阶段已确定“哪里需要解释”；本阶段确定“词典如何解释与匹配”。
    每个审核项对应一个有界词条操作，不重新标 span，不判断整句话是否仇恨，不用模型表现倒推释义。右侧是修复提案，不是已核准答案。
    
          
    推荐审核顺序
    1. 读原词典记录、保留 span、删除反例和待判断问题，确认本条实际用法。
    2. 核对每个义项的释义：对象、用途和必要语境是否完整，有没有确定性过强的表述；再选择义项类别。
    3. 只登记已核实的显式变体，最后核对上下文过滤条件。无需改动的字段保留即可。
    4. 选择决定，必要时填写理由，然后“确认并继续”。自动保存只保存草稿，不表示批准。
    
          
    四种决定有什么区别？
    1 · 批准提案
    原样采用完整提案。若已经编辑，不能直接批准；可选择“修改后采用”，或明确恢复原提案。空义项不可确认采用。
    2 · 修改后采用
    采用右侧编辑后的完整词条。修改释义、类别、变体或规则会自动切到此选项；义项 ID 保持稳定。
    3 · 暂缓
    仍不确定释义、事件指涉或匹配条件时选择，并写明缺什么证据。确认后锁定，但不计入冻结完成，需要后续解决。
    4 · 不采用提案
    明确不同意此次修复方案，必须写理由。不等于删除原词条，也不会自动解除冻结 span 的覆盖约束；若留下冲突，后续验证仍会阻断。
    
          
    本轮需要特别留意
    • 重复组应合并为一个规范词条，保留确实不同的义项或类别；不是机械删除不同定义。
    • “屌”需要说明当前骂人用途；“它”的贬损用法依赖“乱吠”等协同语境，不能把普通指代全部解释为辱骂。
    • “老黑”等表达不能固定为一律中性；“yp”不能仅凭现有词典断言当前义项。
    • “丰县”的高度关联事件是候选解释线索，不应写成“丰县＝该事件”；地理用法与可能的事件指涉应区分。
    • 外部证据可支持事件事实，不能替代原帖语境。无法形成可靠释义时，宁可暂缓，不填猜测性定义。
    
          
    上下文规则：过滤，不生成
    候选只能由 term、显式 variants 与 NFC / 全角 ASCII 折叠 / ASCII 大小写折叠产生。上下文正则仅过滤候选：exclude_any 优先，require_any 满足任一条即可。left/right 各 16 个 Unicode 字符；context 是左文＋候选词面＋右文；surface 是候选本身。合格后才进行全局最长不重叠选择，不设嵌套特例。
    当前确认只验证字段结构及受限子进程中的规则编译，本页不执行正则预览，也不代表已验证语义覆盖。整体覆盖、运行预算（每规则匹配 5 毫秒、每查询 100 毫秒）和盲审是后续门槛。人工可阅读完整语境，但规则只看固定窗口；例如“它”与“乱吠”相距超过窗口时，人能判断协同贬损，不表示规则也能看到该证据。
    词条资格过滤不等于逐处义项消歧：结构化多义会一同用于确定性渲染，不能据此宣称模型已经选中正确义项。存在待判断问题的提案，采用时必须备注核实依据；资格规则未决时必须先补规则，或暂缓。
    
          
    新增词面不一定需要新建词条
    如果新词面应作为已有词条的变体，请在所属既有卡加入 variant，并将该新词面卡选为“不采用提案”，备注“不单独新建”与归属。不要让两个词条同时拥有同一词面，否则全局验证会阻断。ASCII 大小写等价形式通常由受控规范化覆盖，无需重复添加。

    保存、锁定与快照
    服务器是权威会话，保存使用 revision 比较避免多页面互相覆盖。发生冲突时，先载入服务器版本，本地草稿保留供核对恢复；不会自动覆盖已锁定项。下载快照前会保存当前合法草稿；快照只记录当前进度，不会自动冻结阶段。只有零未决、零暂缓并通过后端验证才可冻结。
