## 建议审核顺序

1. **先审48条查询。** 核对目标词实际含义、作者立场、全文是否另有攻击，判断“有／无／未决”，再判断自然度。需要改写的原文可以直接留下修改建议。
2. **再审108条示例。** 每条示例先按自身全文核对答案。O表示普通义，S表示贬损义，B表示其他词面的背景示例；这些设计身份不自动证明标签或关系正确。
3. **最后审关系。** 分开判断“词义／所指信息是否可迁移”和“哪条判断规则适用”。direct／partial／none／unclear都可以保留；示例正确、关系适用、模型受益不是同一件事。

## 如何留下裁决

工作台默认所有人工字段为空。“将AI建议填入当前草稿”只复制建议，不算确认；文本自然度还需自己选择。“保存草稿”可以续审，“确认此项”才记录该项明确决定。已确认项可写明原因后重新打开，旧版会保留。

在浏览器中填写审核人，并在完成或中途暂停时点击**导出审核 JSON**。浏览器存储仅作本机暂存，导出的文件用于交付和跨浏览器续审；导入会核对包版本及原文哈希。修改建议不会直接覆盖本包原文，也不会自动使旧关系继续有效。

也可以在当前任务直接按ID回复，例如“D03改为……；C-T04-S4需要改写；R-C15-I1的规则关系改为partial，因为……”。若整批采纳，应明确你采纳的是查询答案、示例文本／答案还是关系字段；没有明确采纳的字段继续保留待审。

## 数据与检查

- [materials.json](materials.json)：原文、AI答案建议、构式、来源、暴露和待审字段。
- [relations-ai.json](relations-ai.json)：576条带具体信息、理由、限制、原文跨度和实际呈现位置的 AI 建议。其 source_quality 的 accepted 仅是 AI 建议，provenance.adoption 全为 none。
- [relations-unreviewed.json](relations-unreviewed.json) 与 [review-decisions-blank.json](review-decisions-blank.json)：1152维关系字段及全部人工裁决仍为空；没有把本次“开始准备材料”当作逐项采纳。
- [conditions.json](conditions.json) 与 [model-inputs-preview.jsonl](model-inputs-preview.jsonl)：每查询14条件，共672份原样提示预览。A/I由查询当前义项映射O/S，固定四示例的答案位置为无、有、无、有；所有预览都标记不能用于执行。
- [token-pair-checks.json](token-pair-checks.json)：384组单示例替换，完整长度、替换区间及其余token身份／绝对位置一致。每查询的13个四示例条件等长；M00作为无参考供体另列。
- [history-and-family-review.json](history-and-family-review.json)：历史去重范围及跨划分最近邻原文。自动相似度是复核线索，不能证明自然样本独立。

最终提示为579–732 tokens。独立 CPU 核对重建672份提示、1344个候选答案边界、672组同查询供体token映射和全部关系schema。没有加载模型权重、计算预测、按G或准确率选材料，也没有 GPU 执行。

本批用于清晰、受控的语用对照，立场和攻击线索较显式；不覆盖隐含反讽、复杂多轮对话或自然语料的全部分布。示例池复用、同一作者和共同任务框架的依赖继续保留。词形跨度已机械核对，部分立场／独立攻击跨度目前圈定全文作为审核范围，需人工细化，不能据此宣称最小充分语义位置已经定位。
