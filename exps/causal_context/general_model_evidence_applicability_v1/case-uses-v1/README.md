## 更新方法

每个 query_id 分成 hate、group 两行。原 bucket 保留用于解释选样历史；新行为根据审核参考计算，固定四位次序为 C0、S、D、SD。S 为去显式类别字段的冻结词典，D 包含原示例正文和答案。四条件“稳定”不替代六条件的类别字段比较，六条件明细始终保留。

事实字段与用途建议分别保存。事实包括原／审核标签、四位型、六条件预测与分数、材料确认、字段采纳来源。建议包括稳定正确对照、持续错误诊断、示例或词典增量对照、组合正确或错误对照；同一任务可以有多个用途。任何这些建议都不直接成为已证实的机制解释。

资源筛查沿用原计划第二步的窄口径：示例任务参考可用，原答案与审核标签一致，而且已采纳的话题关联、规则关联均为 none，才进入严格 U 候选列表。partial、unclear、未采纳字段不自动转为 none。原答案与审核答案不同的示例单列，不认定为已经排除政策差异的源数据错误，也不混入“标签一致但不适用”的主要对照。

本次 **28/64 个任务没有严格 U 候选**。这只表示当前材料不满足该分支的筛选条件，不影响参考分析，也不排除共享义项、具体命中边、答案修订或其他明确定义的输入对照。U 候选存在时，仍需确定具体集合，再检查 L_R/L_U 与共享来源；不把所有候选自动组成 U。

最终采纳记录存在时，只读取其 values 中对应的已采纳字段；操作适配器的其他字段不会成为新的人工结论。此前 AI 逐项产生、后来被用户整批接受的字段保留完整来源，原逐项确认记录也按原身份保留。关系记录的 native reference_eligible 不作为“话题／规则已裁决”的替代，因为它是不同用途的资格字段。
