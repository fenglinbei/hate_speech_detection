# 攻击严重度量表：讨论草案 v1

状态：AI 提案，2026-09-11。来源为用户在第三批个案裁决后提出的研究问题。本文未启用新标注政策、未给既有记录批量赋分；下列数值例子均未获用户逐项确认。现有 hate/group 裁决另见 [第三批用户裁决](batch-03/user-decisions-01.json)。

## 目的与研究依据

建议增加强度维度。二分类回答某句是否符合本任务的攻击纳入标准，并不说明所有 hate 样本具有相同严重程度。新增有序分级可保留轻度贬损与暴力主张的差别，也便于观察模型在哪些程度上容易误判。但增加刻度本身不等于提高测量质量，还需要固定定义、锚点与一致性检查。

已有研究提供了可参考的设计思路：

- HaSpeeDe 2018 的任务论文 §3.2 介绍其来源 Twitter 语料同时标注二元 hate、强度 0–4、攻击性和冒犯性等维度；正式共享任务使用的是简化后的二分类格式。这说明强度与任务标签可分开保存，不能误称该比赛直接评测了完整强度量表。[原论文](https://ceur-ws.org/Vol-2263/paper010.pdf)
- Measuring Hate Speech 使用侮辱、羞辱、地位贬低、非人化、暴力等多个有序项目，再用 Rasch 模型构造连续分数。本提案只借鉴分维度测量的思路，并未复现该测量模型，其英文语料和群体范围也不等于本任务的中文口径。[原论文及附录 A](https://aclanthology.org/2022.nlperspectives-1.11.pdf)
- Davidson 等区分 hate、其他冒犯性语言和两者皆无，提醒我们不应仅凭用词粗俗程度识别 hate。本任务已将部分个人辱骂纳入 hate/others，需明确说明自己的操作定义，不能将本任务标签直接当作其他语料的同义标签。[原论文](https://arxiv.org/abs/1703.04009)

## 推荐的最小方案

保留 `hate`、`group`，增加一个可为空的有序字段 `attack_severity`。建议名称为“攻击严重度”：它评估当前可见文本中作者认可的贬损及伤害主张，而非标注者本人被冒犯的程度、作者情绪激烈程度、预测置信度或已发生的现实伤害。

| 等级 | 建议锚点 | 判断重点 |
| --- | --- | --- |
| 0 无攻击 | 中性讨论、普通赞同、单纯反驳攻击；没有另外认可的贬损或伤害主张 | 仅涉及身份或出现被反驳的攻击词不升级。 |
| 1 轻度贬损 | 轻蔑、挖苦、轻度负面概括 | 已具有贬损义，但尚无下列较强内容；不是所有玩笑都算 1。 |
| 2 明确侮辱 | 直接人格羞辱、侮辱性归类，或明显的群体污名概括 | 区别于普通质疑和行为批评；低俗词、缩写或重复次数不能单独决定等级。 |
| 3 严重贬斥或排斥 | 将对象认定为天生低等、不配作为人，或主张因其身份剥夺平等参与和基本权利 | 看命题是否否定人的地位或权利；泛用的“垃圾”骂词不自动等于非人化。 |
| 4 暴力认可或主张 | 将针对人的身体伤害合理化、赞许，或直接威胁、鼓动此类伤害 | 仅叙述、引用反驳或中性讨论暴力不升级。 |
| null 待定 | 可见证据不足以在上述等级间作可靠选择 | 保留具体缺失信息，不以 0 代替未知，也不取中间分折中。 |

这些边界是待校准的操作性提案，不是已验证的通用心理量表。0–4 只有顺序含义，不能说 4 是 2 的两倍严重。不同等级也不保证对每位读者产生相同感受。

为减少单一数字的信息损失，建议沿用表达类型与证据摘录，并补记必要的伤害形式：一般贬损、人格侮辱、群体污名、非人化、排斥／剥夺权利、暴力正当化、暴力威胁／号召。形式允许多选；例如认可殴打与号召大规模杀戮即使同处最高档，仍须保留不同的命题内容。现有 `expression_types` 并不包含这些完整选项；具体字段与接口若采用量表，再统一设计。

## 应用规则

1. 先识别对象、命题与作者立场，再评级；引用的攻击不自动算作者攻击，反仇恨语句中的独立辱骂也不自动消失。与现有 hate/group 使用同一份可见证据。
2. 对每句保留支持等级的短引文与一句理由。若同句含多项获认可的攻击，整句分取其中有证据支持的最高等级，形式与对象在说明中分别保留；不能把最高等级传播给所有提到的群体。
3. hate 与严重度分别判断。轻度 hate 仍可保留 hate；不把全部 `non-hate` 自动赋为 0，也不以 `severity >= 1` 自动重算二分类。
4. “这句话是轻度攻击”与“是否攻击尚不确定”要分开；null 必须对应不确定性，不能用低分表达低置信度。
5. #3281 关于严格／宽松阈值的说明保留在理由中。如需另比较阈值，先定义可复现的替代政策再单独输出结果，不逐例随意切换当前 hate 标签。

## 小规模校准与分析

建议先在已讨论、获准使用的材料中选约 20–30 项，覆盖 0/1、1/2 等相邻边界、隐晦贬损、引用反驳、强词弱攻击、平静语气的暴力认可和缺语境样本。这里的数量是工作量建议，不是统计充分性的保证；不打开保留案例或查询原答案来帮助评级。

日常流程可继续 AI 起草、用户集中处理争议，沿用每批暂停讨论的方式。若要报告标注者间一致性，校准子集应由至少两名标注者先独立评分，保留各自原值，再讨论分歧；看过 AI 或另一人答案后的最终裁决不能充当独立一致性证据。只有一名人工时，可间隔一段时间、打乱顺序并隐藏旧分复评，报告个人重测一致性，不能称为人工之间的一致性。

优先查看相邻等级混淆、需要补写的边界与各等级分布。独立评分可用有序 Krippendorff alpha；恰为两名且共同评分完整时可用加权 kappa，并说明样本量及权重。校准中若 1/2 长期无法稳定区分，合并等级可能比保留细刻度更合理。这些是建议的检查方法，当前尚无一致性结果。

采用后，先报告各严重度层的样本数与分类表现，并将 null 单列；有序预测可报告混淆表和级距误差，不能把编码差等同于现实伤害差。与既有基准的二分类结果保留独立口径。既有样本未补评的严重度保持未标，而非根据 hate、关键词或当前人工标签自动生成。是否拟合连续测量模型，应留到有足够独立、多项目评分后再决定。
