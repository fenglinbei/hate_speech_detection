# 内容拆分设计草案 01

建议先固定原背景和示例位置，拆开两案例已显示作用的具体内容。541 用四格设计分离主题与规则；3169 用两组保留正确 hate 标签的词形配对，分别观察群体代称用法和普通笑声用法。

本文件及 design.json 是依据最新结果编写的设计草案。尚未生成完整匹配材料、取得本批人审或形成可执行冻结，也未启动 GPU。既有材料接受只绑定过去的具体文本，新句子的标签和用途需要按本批完整文本核对。

## 从什么证据出发

上一轮 3169 的六项配对内容对照在原标签、NCC 和 A/B 下均为负；541 的六项在 NCC、A/B 下均为正。但是 NCC 的 36 个条件全判 hate，A/B 的正反映射预测差异明显。因此本轮的核心读数是条件间的连续分数变化，同时完整报告最终预测。不能用纠错与否代替对内容效应的检查。

来源：[已封存结果解读](../../label-calibration-results-v1/INTERPRETATION.md)。design.json 绑定当前结果、冻结协议、位置记录及标注偏好快照的哈希。

## 541：性取向主题 × 明确反泛化规则

固定查询、完整词典、其他九条示例，以及示例 826 所在的第 5 槽。每套措辞准备四格，预期正确标签及展示答案都为 non-hate。

| 条件 | 性取向主题 | 明确反泛化规则 | 正文应表达什么 |
|---|---|---|---|
| T0R0 | 无 | 无 | 关于另一种身份／爱好群体的中性事件描述 |
| T1R0 | 有 | 无 | 关于性取向身份的中性描述，同一事件与叙述骨架 |
| T0R1 | 无 | 有 | 在另一群体中反对从个人行为推到整个群体 |
| T1R1 | 有 | 有 | 在性取向群体中表达同样的反泛化规则 |

T0 仍保留“个人属于某个群体”的结构，例如球迷身份；不能简单换成书店或桌面物品，使主题变化同时成为人群结构变化。每套文本固定人物、事件和作者立场。若用虚构人物替换原文中的吴亦凡，四格一起改变，并单列从旧材料到新共同背景的桥接。

R0 是没有反泛化论证的中性叙述，不是主动赞同泛化。R0 中也不能偷偷加入“不能因此评价他人”“这与身份无关”等等价规则。R1 不直接提供查询答案；应让读者从示例内容理解其规则。

先做两套措辞，共八个条件正文。一套可以接近原句表达，另一套换用不同词汇表达规则，减少只靠“讨厌／群体”等查询重合词解释结果的可能。两套措辞仍不足以证明抽象规则学习。

每套预列五项比较，以 m 表示该口径下 non-hate 减 hate 的分数：

- 无性取向主题时的规则效应：m(T0R1) − m(T0R0)。
- 有性取向主题时的规则效应：m(T1R1) − m(T1R0)。
- 无规则时的主题效应：m(T1R0) − m(T0R0)。
- 有规则时的主题效应：m(T1R1) − m(T0R1)。
- 主题与规则交互：前两项规则效应之差，即 [m(T1R1) − m(T1R0)] − [m(T0R1) − m(T0R0)]。

规则效应在两类主题中都保留，才支持跨这两种主题的迁移；主要在性取向主题中出现时，优先考虑主题与规则共同作用。不能仅因 T1R1 最好就宣布两因素都有贡献。

## 3169：先做两组保持 hate 标签的词形配对

固定查询、完整词典、其他九条示例，以及示例 3660 所在的第 3 槽。这里有一个关键限制：直接把攻击改成无攻击，正确示例标签往往也会变化。不能把中性新句继续标作 hate，再称为纯内容对照。

第一组保留原群体贬损命题与指向，只改变称呼方式；第二组保留同一句个人辱骂，只改变明确作为笑声出现的字形。根据当前已确认的严重度—hate 规则及既有个人辱骂锚点，两组目标都是保持 hate。是否实际保持，仍以新全文审核为准。

| 配对 | 左条件 | 右条件 | 能回答的问题 |
|---|---|---|---|
| 群体代称用法 | 原命题中保留“嘿嘿” | 同命题中用明确类别称呼代替，例如经核对的“黑人” | 该语境中的代称形式与显式称呼，迁移影响是否不同 |
| 普通笑声用法 | 个人辱骂中明确写“嘿嘿地笑” | 同句用其他普通笑声，例如“哈哈地笑” | “嘿嘿”在笑声用法中是否也有额外影响 |

上述短语只说明操作方式，尚未通过全文自然性、标签或 token 匹配审核，不是冻结材料。第二组可以基于“你这个蠢货，居然还……地笑”的个人辱骂骨架；不能让“嘿嘿”仍被理解成某个群体或被称呼的人。

每组做两套措辞，合计八个条件正文、四项主比较。群体代称配对需要核对攻击对象、命题及强度是否保持；显式称呼可能提高指代清晰度，因此其效果应按“代称替换为显式称呼”解释。个人辱骂配对允许 group 类别与原群体攻击不同，本轮固定的是 hate 标签，不伪称所有语义标签都相同。

两组的替换方式不同，不把它们硬写成纯粹的“字形 × 攻击有无”四格交互。先分别解读每组中的词形差值：

- 两组均稳定出现“嘿嘿更推动 hate”，与这两种语境中的共享字形关联相容。
- 只有群体代称配对明显，优先检查该语境的指代解释及代称使用。
- 两组都不稳定，则原来 D−C 的效应可能更多依赖其他攻击命题、指向或措辞差异。

这些解释均是当前有限对照下的假设分流，不是“字形本身”或内部机制已被证实。

## 材料准备、审核与冻结

1. **写完整材料。** 先准备 16 个主条件正文槽位：每案例四类、每类两套措辞。能逐字复用的既有文本单独记录，不重复算作新接受。输出正文、修改点、预期 hate、因素状态和剩余混杂。
2. **做输入匹配。** 每个已登记对照匹配完整提示的 token 长度，以及示例正文／答案、后续示例、查询和生成起点的位置。仅核对字数或总 token 数不够。若原目标长度放不下自然表达，统一使用新的共同长度，并单列原输入到该背景的桥接；不靠随意重复标点凑平。
3. **审核具体句子。** 核对正确标签、实际指向与作者立场、所需内容因素是否成立，以及有无新增非预期含义。标签改变的句子应重写或转为另列的“内容＋答案联动”实验，不能静默沿用错误答案。规则／自然性接受不扩展为新的机制判断。
4. **冻结后评分。** 冻结精确文本哈希、完整提示及 token 位置、人审回复范围、条件／比较系数、桥接与基线、三组评分和数值界。固定查询与词典，不因正文改写重新检索。旧 36 条件及全部结果保留，新内容用新版本。

本轮先用原 R 背景；原始输入和既有 C/D 用作单独登记的重放与桥接锚点。位置、长度、词典释义和 A/B 编码规则不同时作为新因素扩张。完整提示数量、桥接数量及 GPU 规模在材料定稿后确定。

## 三组结果继续并列

保留原标签总分、平均分与 EOS 辅助口径；NCC 沿用原来的完整标签公式、五探针和单探针／留一诊断；A/B 正反映射分别报告。**每个新内容条件重新生成并评分五个探针，不能套用上一轮的背景分数。** NCC 同时展示原均分变化、背景变化与残差。

比较各口径内部的效应方向、措辞一致性与数值界，另表记录分类结果。沿用现有 epsilon 及传播公式，不因新结果调整探针、阈值或只选较好的映射。全部反向和未决结果保留。

等主内容对照明确后，再另建少量有新 ID、独立参考的功能性查询，核对普通笑声／明确攻击、反泛化／主动泛化的选择性；避免把所有输入统一向某一标签移动误认为合理利用规则。这一扩展另行审核和冻结，不替换当前两个查询，也不并入保留集。
