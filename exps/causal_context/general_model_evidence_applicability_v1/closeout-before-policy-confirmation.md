## 3. §3.2：可审阅的规则稿已完成

规则稿将已有约定与本轮提案分开：

- 继承当前任务要求：作者立场、实际对象、hate/group 独立判断；原 Gold 使用确定性四元组投影。
- 明确引用/反驳/反讽/自述与群体泛化的处理，区分普通负面评价与可证实的攻击；词典命中和示例答案都不能直接决定查询标签。
- 对纯个体/机构冒犯、个人/机构是否属于 others、国家/民族等归类边界，现有来源不够统一时采用 `policy_ambiguous`。这是推荐的保守规则，不宣称仓库已有完整原始标注手册。
- 区分 `[]` 与 `null`，以及原标注状态、参考可用性、提交进度；未决可确认提交，但不进入依赖硬参考的结论。
- 用户随后要求减少手写并改为 AI 初稿、人类修改。当前 draft.2 将人类操作压成“材料与 AI 初稿核对 → 原标注与结果对照”，取消原 A/B/C 中人工先写、最后揭示 AI 的要求。已有旧记录只读引用，记录类型为 `human_with_ai`，历史暴露如实保留。

常规及多数异常项可由选择题、原文点选及 AI 短说明完成；只有现有选项无法表达时需简短手写。实际省时和准确率尚未测量。原附件计划保持历史原字节，此次有明确用户依据的流程修订以 draft.2 和精简设计为准。

**当前规则状态：待负责人确认，未冻结。** 规划 §3.2 写明“新增 `annotation-policy-v1.md`，由项目负责人确认”。本轮已经把待确认的具体内容写入文件；用户要求按计划启动工作，不等于已经认可这份新产生的语义规则。

## 5. 本轮验证与复算

核验回执记录实际检查范围：配对 manifest 与来源 identity、冻结词典、授权 discovery 索引与卡文件哈希、任务字段完整性、示例身份一致性、资源集合闭合及上述统计。回执不声称已完成精确 span 审核、原模型数值复算或人工审查。

在仓库根目录用系统 Python 复算到临时文件：

```bash
python exps/causal_context/general_model_evidence_applicability_v1/audits/verify_baseline.py --output /tmp/evidence-applicability-baseline-audit.json
```

此核验器使用本机完整封存材料；缺少上游原始分数/包时会明确失败，不是仅依赖公开卡片的通用导入器。输出文件须为新路径，避免覆盖既有回执。若仓库搬迁，用 `--root` 指定新根目录，并用 `--map-source-root` 显式声明冻结记录中的旧根目录；所有来源仍逐字节校验，不能按同名文件自动替换。

本轮只新增计划副本、规则提案、收束记录和 CPU 核验材料，并更新研究入口。已有实验结果、人工记录及服务状态不因这些文档发生变更。规则确认是本轮接续正式新审核前的剩余决策；第二、三步的输入评分与内部干预另有独立门槛。
