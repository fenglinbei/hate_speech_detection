通用匹配机制固定为：

1. 仅 term、显式 variants 和 NFC / 全角 ASCII / ASCII 大小写规范化产生候选；本版 variants 全空，不额外猜测变体。
2. 同词同位置候选去重，保留生成来源；上下文条件只过滤候选，不能生成/扩张 span。
3. 左右各规范化文本 16 个 codepoints；exclude-any 优先，require-any 任一通过。
4. 合格候选按原文长度降序、起点升序、稳定 ID 排序，贪心选择不重叠 span，再按原文顺序输出。
5. 同词多次命中只注入一份解释，保留全部位置；不同词条规范化词面碰撞显式失败。
6. 不做词典 top-k 截断。总长仍为 8,192，超长显式失败，不静默裁剪。
7. 固定词条/义项 ID、匹配版本、渲染版本、Unicode 数据版本、regex 版本和哈希。

## 明确保留的局限

- 7 个新词条的结构化 `senses.definition` 仍为空：**呆比、宁、掉的一批、盖盖、蝲蝲蛄、褐兰州、黑人喃**。不补写任何猜测义项；兼容 `definition` 字段仅用固定文字“未提供释义（冻结时为空；未补写）”。类别仍按获整体采纳的提案保留，不把缺失标记当成真实解释。
- 空释义词条仍参与候选及最长选择，可能遮蔽较短词；这是本冻结资源的已知条件。解释字段消融的后续分析应区分这些缺失项，不能当成拥有完整解释。
- YP 的两个义项已由用户补齐，最终按其保存内容采用，不再列为空释义。
- “它们”的原资格问题并未被证明解决；“它”的局部规则和“交给语义层”的备注同时如实记录。当前未实现自动语义召回筛除或逐处义项消歧。
- 多个义项按固定格式拼接；兼容 category 为类别并集，逐义项类别关联保留在 senses 中。definition 不夹带类别标签、审核备注或提案理由，避免污染后续 Definition-only 条件。
- 对既有 39 句 span 参考的静态诊断为 **37/39 完全相同**；差异仅为两句中的额外“同志”“它们”“尼”命中，与本次保留的宽松策略一致。没有为提高这一数字继续优化；该数字不是新模型实验或旧修复流程验收通过。
- 整体采纳不等于全部词条已独立人工核实。本版无新增 GPU 运行、无额外人工审查、无盲审完成声明。

## 使用和复核

新机制研究使用以下资源参数，而不是复用旧 v0 的 829 条 / top-k=5 配置：

```json
{
  "lexicon": "data/lexicon/annotated_lexicon_mechanism_frozen_v1.json",
  "expected_lexicon_count": 833,
  "exact_top_k": -1,
  "max_sequence_tokens": 8192
}
```

核心检索器由词典顶层 `matcher_policy_version` 启用新路径；pilot 入口也必须实际走受控分支。不能在旧 substring 分支仅将 top-k 改成 -1。正式 category-free Stage1 不在本次改造范围。新研究必须使用新的 context/build ID，不覆盖或重标旧实验结果。

从仓库根目录复核（仅 CPU；不写文件）：

```bash
.conda/stage1-p0/bin/python scripts/stage1/freeze_lexicon_mechanism.py --check
```

复核会用保全的会话与原词典重建内存结果，并逐一比较词典及所有冻结 JSON。依赖固定 `regex==2026.4.4`，来源、构建代码或环境绑定不一致时会失败。首次生成使用同一命令去掉 `--check`；不同内容的已存在产物绝不覆盖。后续确需改资源时应发布新版本，而不是原地修改 v1。
