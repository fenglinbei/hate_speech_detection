## 已决定的方向

- 暂停词典相关实验，不继续人工标注、扩词、逐词优化或修复前后对比实验。

## 可批量冻结的通用机制

| 机制 | 拟冻结行为与边界 |
| --- | --- |
| 同词归组 | 829 源记录、818 唯一 term、11 重复组。829 个三元组均不同，不能直接删除 11 行。按 term 聚合，原样保留不同类别/释义及来源记录。 |
| 结构化类别/释义 | 原词典 65 条记录含逗号分隔的多类别，可机械拆成类别数组；保留每条原释义与其类别的关联。兼容渲染只编号拼接，不用 LLM 改写，不宣称上下文义项消歧。 |
| 候选去重 | 同词条、同位置仅一个 candidate，保留所有生成来源。 |
| 注入去重 | 同词条多次出现只注入一次，保留全部位置；不把出现次数误作多份解释。 |
| 最长不重叠 | 合格候选按原文长度降序、起点升序、稳定 ID 排序，贪心选择不重叠候选，再恢复原文顺序；不是中文分词或最大总覆盖。 |
| 受控规范化 | NFC、全角 ASCII/全角空格折叠、ASCII 大小写折叠，保留原文位置。不得自动繁简/谐音/形近字/模糊扩展。 |
| 候选来源封闭 | 仅原有 term、已声明 variants、受控规范化；原词典没有 variants，首版不自动创造变体。 |
| 冲突显式失败 | 不同词条的规范化词面或同一 span 冲突必须报错，不能由文件顺序静默覆盖。当前规范化无跨 term 碰撞。 |
| 不截取 top-k | 全部合格匹配进入后续上下文构造；总长度仍是工程限制，保留 8K 配置与显式超长处置，不暗中裁剪资源。 |
| 可复现追踪 | 固定词典 ID、规则/规范化/渲染版本与哈希；记录原文 span、过滤原因、重叠淘汰原因。旧缓存和 prompt 账本不得冒充新版本。 |

上述匹配器已在 `src/rag/controlled_lexicon_matcher.py` 实现并通过现有 6 个单测，`src/rag/core.py` 有接入口。但原 JSON 没有顶层 `matcher_policy_version`，直接使用原文件不会启用新机制。无损归组与冻结构建步骤仍需实现；不是把原文件改名即完成。

旧 mechanism pilot 还冻结了 `exact_top_k=5`。其旧分支执行 `hits[:top_k]`，不能简单改成 -1 来表示不限量，否则会少取最后一条；必须实际路由到受控匹配器。正式 category-free Stage1 是另一条管线，本次不顺带改造。新冻结资源必须使用新 build/context ID，不复写已有 v0 prompt、生成或 margin 账本。

## 已有人工确认的局部规则：单独列示

以下 5 条排除规则可以依据既有确认批量移植，不需要再发起一轮标注，但它们是有界局部规则，不是普适中文边界识别：

| term | 字段 / pattern | 作用 |
| --- | --- | --- |
| 基 | right / `^(?:本\|因)` | 排除“基本”“基因”中的命中。 |
| 你妈 | right / `^妈` | 排除“你妈妈”中截出的“你妈”。 |
| 国女 | left / `韩$` | 排除“韩国女…”中的命中。 |
| 国男 | left / `(?:中\|德)$` | 排除“中国男…”“德国男…”中的命中。 |
| 厌男 | left / `讨$` | 排除“讨厌男…”中跨词界命中。 |

另外，“它”的确认记录仍有 context require `掀它东西`，但审核备注明确写“不在正则过度处理，交给后面的语义召回层”。该条与具体句面绑定，不能当作普适贬损指代规则；建议首版不移植，原审核结果原样归档。“批判”中的“批”等其他草案尚未确认，不能把未审规则冒充批准。

正则框架若启用：仅判断已生成候选的资格，左右各规范化文本 16 个 codepoints，exclude 优先、require 任一满足；每条最长 256 字符、每词最多 8 条、单次 search 5ms、规则执行预算 100ms。预算不是完整查询硬 deadline；冻结构建需显式核验固定 `regex==2026.4.4`，不能只依赖 matcher 的导入行为。

## 推荐的新冻结版边界（尚未物化）

推荐采用“原词典内容 + 无损归组 + 全部通用机制 + 上述 5 条已经确认的局部排除规则”。不加新词、不猜变体、不重写原定义/类别、不自动选择某个义项、不移植具体句子特判；已确认的 24 条内容修订也先作为独立历史成果保存，不与本次以原词典为基础的机制资源混淆。

最长规则只在已有候选之间竞争；若“基本”不是候选，则仍需要“基”的显式排除规则。没有相应规则的已知误命中和缺词应作为固定资源限制保留，不再逐句修补。

下一步应生成新的、与 `annotated_lexicon_repaired_v1` 人工修复线明确区分的机制资源文件，并绑定来源记录映射、规则清单、匹配/渲染版本、schema 与哈希。只做自动结构、信息保全、碰撞、确定性和兼容性检查，不要求旧人工修复 gold 全通过，不启动人工盲审。现有原词典与旧实验账本保持不变。

本轮只完成暂停、检查点保全和规则报告，尚未生成或宣称完成新冻结词典。
