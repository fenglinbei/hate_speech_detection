# 主评分规格 v1

适用协议：`task-applicability-scoring/v1`。机器规格见 [scoring-spec.json](scoring-spec.json)。此规格固定测量对象；没有把旧 Q01 运行改用新评分，也没有声称新内核已经取得 GPU 资格。

## 模型输入与答案位置

模型固定为本地 Qwen3-8B 基座；使用清单绑定的本地 tokenizer 和原 chat template，`enable_thinking=false`、`add_generation_prompt=true`，不追加人工 assistant 内容。模型权重身份、库版本和数值运行配置在后续执行冻结中绑定并复验。

恰好两条消息：system 是 model-task.txt 的完整 UTF-8 文本，保留末尾 LF；user 依次包含参考词典、参考示例、待判断文本。所有条件使用同一 renderer，禁止偷偷裁剪、strip 或归一化材料正文：

```text
【参考词典】
{词典块或（无）}

【参考示例】
{示例块或（无）}

【待判断文本】
{查询原文}
```

每个词典块为 `词条{1起序号}：\n{一个义项的完整原文}`；每个示例块为 `示例{1起序号}：\n文本：{原文}\n答案：{有或无}`；块间恰好两个 LF。材料按已冻结数组顺序呈现；不自动检索、排序、截断或随示例变化重新生成词典。renderer 不读取任何质量、关系、人审字段或查询参考，只接收模型允许看到的正文和示例答案。无词典或无示例时统一呈现 `（无）`，这是固定格式的一部分，不宣称其为无任何心理效应的零点。

模板渲染后按 `add_special_tokens=false` 编码，保存完整消息、prompt UTF-8 哈希和 token IDs。答案位置是完整模板末尾尚未输入候选时的下一 token 位置；不能把它误取为 `<think>` 内、提前的 assistant 标记或某个示例答案位置。批处理必须按每条输入最后一个有效 token 取预测，不得从 padding 取分；position_ids、attention_mask 和截断规则须通过执行资格检查。主测量不得截断：超长输入先显式报错，不能静默丢失任务或资料。

## 候选与主读数

两个裸候选为 `有`（hate，token 18830）与 `无`（non-hate，token 42192）。冻结 tokenizer 下必须各为单 token，并对每条正式输入验证 `encode(prompt + label) == encode(prompt) + [label_id]`。CPU 示例通过不替代整个新输入帧检查。候选不含引号、前后空格、换行或 EOS。

从**同一次 prompt-only forward 的同一位置**取两个原始 logits，关闭 dropout、显式思考和采样。参考执行使用 FP32 模型计算；将输出 logits 转为 FP64 做减法与 logsumexp 归约。禁止对两候选分别进行两个可能上下文不同的 forward，禁止先加入候选 token 再取分。新的高吞吐实现须对该参考取得资格，不能沿用旧多 token 评分器的已通过状态。

令完整词表 logits 为 z，`A = logsumexp(z)`：

```text
log_p_no  = z[42192] - A
log_p_yes = z[18830] - A
m = z[42192] - z[18830]
pair_support_no = sigmoid(m)
log_legal_mass = logsumexp(z[18830], z[42192]) - A
legal_mass = exp(log_legal_mass)
```

m 是唯一主连续读数，正值支持无攻击，负值支持有攻击；减法直接在两个 logits 上完成，log probability 差用于一致性核对。没有 EOS、长度平均、temperature 缩放、NCC 扣除或阈值拟合。`pair_support_no` 只是两候选内归一化支持度，不叫真实正确概率；legal_mass 是两个合法 token 在完整词表的概率总质量，防止把相对偏好误写成输出遵从性。

每条评分保存 prompt 身份、答案位置、两原始 logits、两个 log probability、m、pair_support_no、log_legal_mass、legal_mass 和数值资格引用。NaN、Inf、越界 token 或缺失 logits 视为评分无效并停止分析，不当作 tie 或 non-hate。

## 分类、平局与数值未决

未经误差带判定的 `raw_prediction` 固定为：m>0 输出无；m<0 输出有；m=0 为 null 且状态 exact_tie。精确平局不按词表序号或参考答案打破。这个 null 是分析状态，不是给模型增设的第三个输出。

另存 `resolution`。运行资格回执须在正式科学评分前提供覆盖相应输入形状和数值运行方式的非负 `margin_error_bound=b` 及其计算、测试来源；这是工程可复现性的约定误差带，不冒充真值的统计置信区间。没有回执时 b=null、resolution=unqualified，不使用默认零界，也不借用旧 JSON 候选的误差界。

有有效 b 时：m>b 为 resolved_no；m<−b 为 resolved_yes；`|m|≤b` 为 numerical_unresolved，精确 m=0 另保留 exact_tie 标记。阈值始终为 0；误差带不校准类别先验。运行数值参数及资格回执是后续执行冻结的绑定项，本协议无需知道尚未运行的误差数值才能固定上述算法。观察科学结果后不得放宽误差带来保留期望结论或缩窄它来宣称可分辨。

人工参考未决、关系 unclear、模型精确平局、模型数值未决及非法自由生成分别保存，不能合并成同一个缺失类别，也不能默认归无。

## 配对效应、方向与计数

每个对比在输入冻结中按 ID 固定处理条件 t 和对照条件 c：`Δm=m_t−m_c`。若两个条件查询参考相同且已解决，设 y=+1（参考无）或 −1（参考有），另报 `reference_aligned_change=y*Δm`。正值仅代表分数向参考方向移动，不等于阈值修复。改变查询且参考标签不同的对比保留 Δm，但不套用单一 y；逐查询分别判断正确性。

误差传播使用线性表达式：先按实际评分记录 ID 合并重复物理项；若表达式为 `sum(a_i*m_i)`，误差带为 `sum(abs(a_i)*b_i)`。共享项相消后再传播。任一未消去项 b=null，则表达式数值资格未验证。`abs(effect)>bound` 才报告方向可分辨，等号仍为未决；不把工程可分辨当作统计显著。

对于已解决的查询参考：

- 原始正确率的分母包含全部预定且有效评分的参考已解决项；精确平局计为未正确并单列，不偷偷删去。无效评分是执行失败，未修复前不发布该帧的正式指标。
- 主参考一致性同时报告保守比例（已数值解决且正确／全部参考已解决项）、数值未决比例和原始正确率。尚无数值资格时，保守比例不生成，不能把未验证项当作已解决。
- 修复为对照明确错误、处理明确正确；损伤反之。数值未决或 tie 参与任一端时标为未决转移，另保留 raw 标签变化，不计作已验证修复。
- 无参考项仍可参与预先规定的纯分数对比，但不进入正确率或参考对齐读数。人工待定数量和原因一并报告。

同一查询的不同条件、改写、评分重复和换卡不是独立样本。先列完整配对读数，再按预先固定的家族内比较及家族权重汇总；总体默认家族等权、家族内预定比较等权，不能用条件多的家族扩大权重。不同操作含义的比较分别报告，不把自然删除和占位替换混为一种效应。确认阶段不确定性方法、最小重要效应及科学判据随具体材料计划在开放确认结果前登记；本测量协议不预先宣称效应存在。

## 辅助诊断与实施边界

输出遵从性在预先指定的开发子集独立检查：完整生成的可见答案必须恰为一个“有”或“无”，不先 strip 去掉额外文本以美化通过率；生成设置、终止和 token 上限预先固定。强制两候选评分不冒充自由生成成功。

A/B 正反映射和旧 JSON 桥接只在预先指定的小子集使用，均标为不同输入／编码的辅助诊断。桥接要区分任务文案变化和答案编码变化，不能合并归因。NCC 只在有明确背景偏好问题时另立诊断；不自动扩展到所有材料。具体子集、辅助提示及其生成配置属于后续输入计划，本次没有创建它们。

主候选及计算口径已经冻结。诊断若发现编码敏感，报告边界；不能按结果换用最有利的评分作为主结果。本轮没有执行评分器或 GPU 模型，新评分实现、运行数值资格和正式材料矩阵是随后交付。
