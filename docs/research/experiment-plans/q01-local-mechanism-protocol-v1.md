## 3. 双向估计对象

定义 m=score(non-hate)−score(hate)。对固定 g=(F,N)，

`d_H=m(N_H)−m(O_H)`，`d_A=m(N_A)−m(O_A)`；`C=(d_H+d_A)/2`，`I=d_H−d_A`。

N→O（R）：`r_s=m(O_s←h(N_s,S))−m(O_s)`，其中 s=H/A；`R_C=(r_H+r_A)/2`，`R_I=r_H−r_A`。

O→N（K）：`k_s=m(N_s)−m(N_s←h(O_s,S))`；`K_C=(k_H+k_A)/2`，`K_I=k_H−k_A`。K 的实际移动 `patched−recipient` 另行保存，不能因统一方向的符号约定而隐藏原始负移动。

R/K 均与本口径下的正 C、负 I 比较。每行保留 recipient、donor、patched、实际移动、定向效应、目标、残差、数值界、比例及每臂分数。C 恢复只说明共同移动，不能当作 I 恢复；标签翻转、靠近 donor 和幅度恢复也分别报告。

## 4. 完整标签评分与 NCC

沿用原标签完整 JSON 字符串，包括引号。主口径为不含 EOS 的 `answer_sum`；同时保存 `answer_mean`、`total_with_eos`、`mean_with_eos` 和所有答案／EOS token logprob。A/B 正反编码均用各自完整输入和候选、四种原始分数，禁止跨编码交换 donor。

原标签 hate 为 `[78522,349,1]`，non-hate 为 `[1,6280,2832,349,1]`；A 为 `[29133,1]`，B 为 `[63590,1]`。不能假定首 token 是公共引号，也不能用单个 next-token logit 代替完整标签。

五个探针精确为 `""`、`" "`、`N/A`、`[MASK]`、`Lorem ipsum`，仅替换查询 JSON。沿用完整答案均分归一化、探针概率平均后转 log-odds 的本地 NCC：`b=logit(mean(sigmoid(m_probe_mean)))`，`NCC=m_real_mean−b`。以稳定 log-sum-exp 计算，同时保留五个 single-probe 和五个 leave-one-out 读数。

两种干预 NCC 分开：

1. **固定 recipient 背景**：recipient、patched 与作为恢复目标的 donor 都减去同一个 recipient 的原背景。因此干预效应、目标、残差及恢复比与原均分相同，程序逐项检查物理系数相等。这是代数恒等，不是独立复现，也不能用上表完整重校准的 C/I 做分母。
2. **干预后重新校准**：lexicon_end、demo_answer_end、pre_answer 与 unrelated_demo_end 在五个背景都有相同角色，故每个背景做同方向、同 F／示例词形／probe ID 的交换，再重算 b。所有 single/LOO 均保留。query_hehe 的完整重校准严格不适用；不能把真实查询激活放进背景或临时改成背景末端。

两种 NCC 具有不同估计对象，不能混合排名。N1↔N2 控制采用相同定义，只把左／右词条换成 N1/N2。

## 5. hook 与缓存契约

新实现复用原 FP32、eager、batch-one、无 KV cache、仅投影目标位置的 scorer，旧 kernel 不改动。模型仍通过原 `NumericRunner`、普通文件模型副本、注册 hash 与新鲜 `verified_model_source_lease` 加载；禁止绕过租约或修改共享软链接。

每个 donor 独立运行一次**只有提示**的 backbone forward，采集该提示需要的全部注册角色。缓存键绑定 plan、数值 runtime、来源 context／prompt／token hash、编码、probe、F、示例词形、module、layer、角色及位置；存储 CPU FP32 clone 和向量 hash。两个标签候选与全部 prefix 分支使用同一份缓存。每遍、每个物理 producer 都从冷缓存开始；检查点续接的额外采集独立计数。

执行 hook 只写注册的提示位置，复制 output 后返回，保留 tuple 其他成员。根 forward guard 核对实际 token 前缀、长度、mask、position ID 和 use_cache=False。answer token 不能作 donor 或替换位置。所有 hook 在正常结束或异常时移除；源缓存禁止原位修改。向量范数、差向量范数、recipient 状态跨候选／prefix 的最大变化一并记录，不把激活数值变化的阈值偷换成分数 epsilon。

只采集控制在 candidate scoring 中注册只读 hook 并实际复制状态，但这些带候选的观察状态不能写入 donor 缓存。self-patch 必须写回真实 prompt-only 缓存。attention/MLP 的输出结构在小型随机 CPU Qwen3 模型上检查；其科学干预矩阵仍属于另行冻结的细化阶段。

示例 9 在词条之后，也可能承载其信息，不能要求零效应。N1/N2 自身输入分数不同，也不能当作零效应控制。保留其基线差、双向效应、状态差范数；不通过未注册的范数缩放将控制变成“匹配”。末层 pre_answer 只改变首次预测状态，不保证整个多 token 标签分数等于 donor，因此不作端到端正对照。

工程阶段含基线共 5,072 请求／10,144 候选每遍；科学阶段含基线共 6,944 请求／13,888 候选每遍。每阶段六遍：reference、repeat、padding(+64)、prefix、member_order、replica(shift=1)。12 遍合计 **144,192 次候选评估**，实际评分 backbone forward **214,768 次**，因 prefix 多分支而更多。主网格自身单遍仍为 6,912 次候选评估。

无中断时，每遍每张卡至多额外采集 96 次 prompt-only forward；全流程每卡上界 1,152 次，四卡至多 4,608 次。恢复检查点会重新采集尚需的 donor，按 invocation 单独记录额外次数。缓存采集、模型装载、CPU 验收和 I/O 时间不能从候选数量中推定。本预算不含后续至多 12 个细化单元。

四个物理模型副本参与分工；replica 遍次将每个请求轮换到另一张卡。本设计证明每请求在两个不同物理 producer 上的重放，不声称每请求都在四张卡各执行一次。

工程六遍全部通过才开始任何科学干预遍次。每遍结束后先验收再进入下一遍。真实模型 GPU 资格必须重新获得；CPU 合成生命周期、随机小模型或历史 GPU 结果不能代替它。

## 7. 数值门槛与停止条件

延续 epsilon=`0.0013427734375`，同 logits FP64 arithmetic 参考与重复门槛各 `0.0001`；其余历史／padding／prefix／成员顺序／换卡及工程期望值使用不放宽的 epsilon。检查每个 candidate token、EOS、四种分数、margin；科学阶段进一步检查全部 C/I、每臂读数、NCC aggregate/single/LOO 与残差。

原 margin 界为 ε，C 为 2ε，I 为 4ε；完整重校准 NCC margin 为 2ε，C 为 4ε，I 为 8ε。背景 `logit(mean(sigmoid(m)))` 在输入 margin 的无穷范数下为 1-Lipschitz。程序将各个物理 margin 和完全相同 probe 集的背景作为原子，先合并共享项系数，再按系数绝对值之和传播界。相同单探针背景直接使用同一个原始均分 margin 原子。R−C 等残差应出现的抵消必须保留。数值界不解释为置信区间或样本误差。

任一来源 hash、模型租约、设备身份、token 边界、hook 生命周期、缓存契约、有限值、数值门槛或覆盖检查失败，记录失败、释放本任务 worker 并停止。失败终态不自动重跑，不放宽 epsilon，不自动改评分／probe。已完成运行也拒绝新 forward。运行未完成或验收不全时，分析命令拒绝读取分析参考。

## 8. 候选提名与细化规则

仅原标签 `answer_sum` 决定提名。C/I 分别要求四组×双向全部满足：目标超过自身数值界；效应超过其界且与目标同向；相对零干预，绝对残差改善超过保守数值界 `target_bound+residual_bound`。最后一条将讨论稿的“残差减小”明确为可分辨的改善，防止浮点微小改善触发候选。

只对可分辨的目标计算 `effect/target` 和 `1−abs(target−effect)/abs(target)`，两者均不截断。每个单元按四组×两向的最小 closeness gain 排序；平局依层索引、角色顺序 lexicon_end、demo_answer_end、query_hehe、pre_answer。C、I 各取至多一个，重合去重，总计至多两个。完整失败／反向／未决表照常保存。

A/B、NCC、single/LOO 和特异性控制用于限制解释。它们不能促使程序换选另一个“更一致”的赢家。无合格单元则停止此扫描范围；这不等于模型没有相关机制。

细化需另版协议与输入冻结：仅提名单元的原层及相邻层（裁剪到 0–35），分别 attention 输出／MLP 输出，最多 12 个不同单元。新增模块 hook 重新验收。首轮交付只输出候选提名和异常清单，不自动开始细化。

默认在 16:45 停止接受新请求，当前完整候选对写入检查点后退出；预留 15 分钟保存状态与释放 worker。每请求 fsync，候选对为检查点单位。运行可在完整 pass 后暂停，也可按时间在 pass 中暂停。继续同一 run 必须使用相同物理卡列表、UUID、数值 runtime、计划和未变源码；原分片前缀严格核对，重复完成的请求不会再评分。每次采集 invocation 与 producer 都记录，不能伪称没有中断。

未得到四张满足空闲条件的卡则继续等待，不自动缩成两卡或扩大 pool。窗口结束时停止本次等候／运行；失败或完成也停止轮询。运行期间不占用额外设备，不终止其他使用者的进程。`--through-pass engineering-replica` 可只做完整工程验收；完整执行按同一封存 schedule 接续。

空闲判据为每卡使用显存不超过 1,024 MiB、可用显存至少 36,000 MiB、利用率不超过 5%，启动时再核对 UUID。不能仅凭利用率为零占用仍加载其他模型的卡。定时控制器在 16:55 设置本任务进程的兜底退出期限，留出 17:00 前的清理余量。

`validate`、`check`、`analyze` 都不加载 8B 权重。只有显式 `run` 路径调用模型。定时调度及实际启动回执另存，不能把“已安排”写成“已评分”。分析参考只在所有 raw seal 和验收通过后读入；机制 readiness 始终不自动变为 true。

## 10. 预先判读

| 观察 | 结论范围 |
|---|---|
| C 恢复而 I 不恢复 | 共同分数移动的局部传递，尚不能解释示例词语交互 |
| I 恢复而 C 很小 | 局部交互作用，尚不能解释整体偏移 |
| 四组双向 C/I 恢复、不同口径稳定 | 支持所测状态对固定输入差异的局部中介作用 |
| 单向有效 | 记录方向不对称，不据单向失败断言无关 |
| 示例 9 或中性词条控制相近 | 保留广泛状态传递／填充内容敏感性解释 |
| 仅最终输出端有效，或映射／探针推翻 | 输出编码或测量敏感的局部结果，不升级为义项选择 |
| 注册范围无合格单元 | 报告本局部测试未定位，不能继续无限挑层／头 |

即使 Q01 局部成功，仍需把位置与读数固定后，另验已暴露 Q05、Q03/Q04 与原 3169 的转移边界。共同朝 non-hate 移动不能说明应判 hate 的语境仍被识别。这些材料也不能充作新留出。

方法依据为已查阅的 [Zhang & Nanda](https://arxiv.org/abs/2309.16042) 与 [Heimersheim & Nanda](https://arxiv.org/html/2404.15255v1)。本网格、NCC 两类估计对象、控制预算、数值界和选择规则是针对本项目制定的规范，不能声称论文提供了相同的现成协议。
