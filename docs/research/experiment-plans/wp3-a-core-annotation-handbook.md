## 1. 目的、适用范围与一句话原则

WP3 的正式目标是构建一个：

> **fit-attested、sense-level、ontology-free、verdict-free 的术语理解资源。它解释输入中非透明
> 表达的形式与核心含义，但不预先给出下游任务的类别、判断或当前样本答案。**

本手册用于：

- 人工识别和修订原文中的 terminology mention；
- 将 mention 聚合为 entry 和 sense；
- 对 sense 或待决 hypothesis set 作 A-core、B-contextual、C-quarantine、R-reject 分层；
- 编写可供下游判断者参考的无类别、无裁决证据卡；
- 决定 A/B/C 分别如何进入阶段一的精确边界呈现，以及哪些候选必须以 R 排除。

本手册不用于：

- 识别一条文本是否构成攻击、仇恨或其他下游结论；
- 根据某个表达与数据标注的相关性决定是否收录；
- 扩充一个预设数量的词条；
- 把 Web、LLM 投票、频率或置信分数直接转成正式条目；
- 处理 dev/test 中首次出现、但 fit 中从未出现的 headword。

一句话原则是：

> **A-core 仍按最保守标准收录，不为词条数量降门槛；但资源不丢弃真实存在的上下文不确定性：
> 阶段一把 A、B、可安全精确命中的 C 分别呈现为“确定释义、多个受支持解释、明确未决信息”，
> 只把 R 从资源对象中排除。**

这里的“多收 B/C”不等于把噪声都塞给判断者。只有 fit 中真实出现、边界可定位、通过人工核对且
确有解释价值的表达，才可进入 A/B/C 证据库；语义碎片、透明词、通用辱骂、完整句和 substring
误命中仍属于 R。

## 2. 基本对象：mention、entry 与 sense

### 2.1 Mention：一次具体出现

Mention 是某个原始 fit record 中的一次精确出现：

```text
mention = (record_id, raw_start, raw_end, surface, raw_context)
```

要求：

- `surface == raw_context[raw_start:raw_end]`；
- offset 一律指向不可变 raw text；
- 同一个字符串在两条记录中出现，属于两个 mention；
- 同一字符串在同一句中出现两次，也属于两个 mention；
- mention 的存在只表示“此处可能需要解释”，不表示它必然成为正式词条。

### 2.2 Entry：形式族

Entry 管理有证据支持的 headword 与表面变体，例如：

```text
headword: 国女
surface_forms: [国女, 郭女]
```

只有在变体关系和核心解释均得到证据支持时，两个 surface 才能进入同一 entry。字符串相似、
读音相近或模型认为“可能相关”，均不足以自动合并。

### 2.3 Sense：上下文中的一种解释

Sense 是 entry 在一组 occurrence 中成立的具体核心含义。相同 surface 可以有多个 sense。
A 要求精确 surface 能稳定映射到一个核心 sense；B 可以保存多个均有支持的 sense 及其适用条件；
C 若尚不能形成可靠 sense，只记录待决的 `hypothesis_set`、证据冲突和未知项，不强行补写定义。

例如，某称谓可能分别用于外部贬称、群体内自称、引述或讨论该词本身。这些 occurrence 可以
共享 entry，但不能在没有 sense 区分的情况下冒充一个确定释义。它们可以进入 B 的多解释证据卡，
或在证据尚不足时进入 C 的不确定性卡。

### 2.4 三层关系与证据单元

```text
raw record
  └─ mention（精确 occurrence）
       └─ entry（形式族）
            └─ sense（核心解释与适用条件）
                 └─ evidence tier / rendering policy（A / B / C / R）
```

人工首先裁决 mention 的边界，再裁决 entry 归并，最后裁决 sense/hypothesis set 和证据层级。不得从
一个字符串被抽到，直接跳到“它是一个 A-core 词条”。证据库单位是 `(entry, sense)`；尚未形成可靠
sense 的 C 使用 `(entry, hypothesis_set)`。两者都必须回链到具体 mention，而不是裸字符串。

### 2.5 两层资源：完整证据库与分层 renderer

WP3 把“是否保存信息”和“如何向判断者呈现”拆成两层：

1. **完整证据库**保存 A/B/C/R、fit mentions、证据、反例、原因代码和人工决定，供审计与版本管理；
2. **分层 renderer**只对精确边界命中的 A/B 和 `C_visible` 生成证据卡，R 不生成卡。

判断者不需要看到内部字母、证据路径、confidence 或审核备注。模型可见字段统一为：

```text
表达：<当前精确命中的 surface>
参考信息：<按 A/B/C 规则生成的内容>
适用限制：<如何使用、哪些事项仍需结合原文判断>
```

因此，A/B/C 是内部证据状态和呈现策略，不是三套互不相干的词典，更不是对当前文本的任务结论。

## 3. Category-free 的准确含义

### 3.1 Category-free 不等于 referent-free

正常词义中必要的指称可以出现。例如：

```text
txl：常见为“同性恋”的拼音首字母缩写。
```

这里的“同性恋”是对缩写的词义解码，而不是数据集类别或当前样本结论。若删除这一指称，释义
便无法帮助读者理解 `txl`。

### 3.2 允许写入的内容

- 标准写法、canonical form 或直白改写；
- 字音、字形、缩写、混写、拆分、符号替代等形成机制；
- 有证据支持的核心词义；
- 内部审计平面中的语体、歧义和适用语境；
- “具体语气或说话者立场需结合上下文”等非决策性限制说明。

阶段一只渲染实际精确命中的表达。A 渲染一个稳定核心释义；B 渲染所有受支持的候选解释及适用
条件；C 明示“现有证据尚不能确定”，并且只在有独立支持时列出候选假设。任何层级都不渲染完整
证据原文、内部层级字母、审核判断或未命中的变体列表。

### 3.3 禁止字段、来源和措辞

以下字段及其同义别名不得进入候选纳入依据、sense 定义或模型可见发布块：

```text
category, categories, primary_category,
targeted_group, hateful,
target, argument,
hate_count, hate_precision, non_hate_count, nonhate_penalty,
label, labels, task_prediction,
annotation_count, category_counts, category_purity, log_odds
```

禁止从这些字段复制、概括或反推信息。还应禁止下列决策性措辞：

- “该词属于针对某类人的仇恨词”；
- “看到该词就应判为某一数据集类别”；
- “当前句子的目标是……、论点是……”；
- “该表达说明当前样本应判为攻击/非攻击”；
- “本词因为在某类标注样本中更常见而被收录”；
- 任何把词典命中转换为下游预测规则的提示。

如果一个候选只能通过上述措辞获得“定义”，而无法写出独立、可核查的词义解释，则它不满足
A-core 条件；不得把任务判断改写成词典定义。

## 4. A-core 的六项强制准入条件

### 4.0 先用一句人话理解 A-core

可以把 A-core 想成一张会被系统**自动贴到原文旁边的确定释义卡**：

> 只要这个精确表达出现，我们是否可以不看任务标注、也不先判断整句话，就放心地展示同一条
> 核心释义，而且这条释义基本不会误导读者？

只有答案明确为“可以”时，才考虑 A-core。实际审核时依次问六个简单问题：

1. **真的见过吗？**——这个表达是否逐字出现在 fit 原文中？
2. **它本身是个完整表达吗？**——不是 `女拳不`、`拳在` 之类的语义碎片，也不是整句话？
3. **真的需要解释吗？**——不了解网络语、缩写或特殊用法的人，是否会实质性看不懂或误解？
4. **这条解释足够稳定吗？**——这个精确写法再次出现时，同一条核心释义是否仍然适用？
5. **我们有根据吗？**——释义是否有 fit 上下文、确定性转换或独立材料支持，而不是模型猜测？
6. **能只讲词义、不替任务作答吗？**——释义能否只说明“它是什么意思”，不告诉模型整句该怎么判？

六个问题全部回答“是”，再通过人工核对和精确匹配安全检查，才是 A。A 是“可以稳定断言这一
词义”的门槛，不是“是否保存这个表达”的门槛。否则按原因分流：

- 根本不是完整术语，或本来就能直接看懂：R；
- 可能有特殊含义，但目前证据或解码不够：C；
- 确实是术语，但含义、立场或用法必须看上下文：B。

其中 B 和边界安全的 C 仍可进入阶段一证据卡，只是不能伪装成 A 的单一定义；R 才完全不向
判断者呈现。

几个最直观的对照：

- `txl`：完整、需要解码、映射稳定、可写成纯词义解释，因此可以申请 A；
- `舔狗`：若证据确认其核心网络义稳定，可以申请 A；
- `基佬`：引述、外部称谓和回收用法有明显差别，因此放 B；
- `幕刃`：可能需要解释，但当前映射证据不足，因此放 C；
- `女拳不`：候选本身是语义碎片，因此是 R；原文中的 `女拳` 必须另建 mention 再判断；
- 普通指称的 `黑人`：表达本身无需额外解释，因此是 R。

一个 sense 只有同时通过以下六项，才有资格进入 A-core 确定释义审核：

```text
A_fit ∧ U_unit ∧ G_gap ∧ E_support ∧ P_portable ∧ N_neutralizable
```

### 4.1 A_fit：fit 中有精确出现

要求：至少一个 mention 可以在冻结 fit raw text 中用精确 offset 重放。Web、旧词典、模型记忆
或 dev/test 中出现，均不能代替 fit attestation。

- 正例：fit 原文中逐字出现 `txl`，offset 可重放；
- 近邻反例：Web 上常见但 fit 中未出现的缩写，只能作外部背景，不能成为正式 headword。

### 4.2 U_unit：最小且语义自足

Span 必须是能独立承载目标解释的最短连续语言单位。最短不等于机械地截取最少字符。

- 正例：`女拳不行` 中若特殊义由 `女拳` 承载，可以另建完整候选 `女拳`；
- 近邻反例：候选 `女拳不` 带入否定词，是语义碎片，本身判为 R，不能继承 `女拳` 的层级；
- 正例：若特殊义属于整个 `easy girl`，应保留完整短语；
- 近邻反例：`easy` 不能继承完整短语的含义。

### 4.3 G_gap：存在非平凡解释缺口

不了解音形转换、缩写、网络词义、固定搭配、典故或特殊语用时，读者会实质性误解或无法恢复
当前表达。仅仅“与研究任务有关”“带负面情绪”或“频率低”不构成解释缺口。

- 正例：`舔狗` 不能仅按“舔 + 狗”恢复常规网络义；
- 近邻反例：普通指称意义的 `黑人` 可以直接理解，不因其可能与下游任务相关而收录；
- 正例：`J生虫` 需要解码混合写法；
- 近邻反例：标准写法 `寄生虫` 在普通字面义下没有额外形式缺口。

### 4.4 E_support：核心解释有可追溯支持

每个 canonical mapping 和核心释义都必须由允许的证据路径支持。LLM 参数知识和自报 confidence
只能产生假设，不能独立满足本条件。

- 正例：`J生虫 → 寄生虫` 的字符替换可确定、上下文替换成立，并经人工核对；
- 近邻反例：仅凭一个模型猜测 `幕刃 → 母人`，没有独立上下文或外部证据，不能进入 A。

### 4.5 P_portable：核心义可跨 occurrence 迁移

核心解释不是为某一句临时编造，并且同一拟发布 surface 在适用 occurrence 中不存在未解决的主要
替代义。A 卡不使用上下文 sense gate，因此主要多义不能藏在一个 A 定义里让判断者猜；这类 surface
应转为 B，并把受支持的解释和适用条件显式列出。

- 正例：有证据支持时，`txl` 的缩写映射可跨多个 occurrence 复用；
- 近邻反例：`下半身不能饿` 的含义主要由当前修辞构成，不宜把整句固化成词典 sense；
- 近邻反例：数字 `666` 同时可能是普通数字和网络评价，未解决时不能进入精确匹配 A-core。

### 4.6 N_neutralizable：可写成无类别、无裁决的核心释义

释义必须能独立陈述“它是什么/表示什么”，而不是陈述“当前样本应该怎么判”。

- 正例：`txl` 可写为“‘同性恋’的拼音首字母缩写”；
- 近邻反例：“这是一个看到后就应判为某类攻击的词”不是词义；
- 正例：`舔狗` 可解释其关系行为模式；
- 近邻反例：只写“这是骂人的词”信息不足，也把语用判断误当成核心义。

### 4.7 A-core 的额外确定释义门

通过六项准入条件后，还必须满足：

1. 拟发布 surface 通过精确边界与 substring 安全检查；
2. 同一 surface 不存在第二个未解决的 A/B sense；
3. 核心释义通过“替换后原句基本保持预期含义”的人工检查；
4. 已完成人工审核，疑难项已经处理；
5. 禁止字段和决策性措辞扫描为 0；
6. provenance、fit mention、证据与审核记录可重放。

任一门未通过，均不能因“词很重要”或“词条太少”而破例升为 A。满足 B 或 C 条件时应按对应
策略呈现，而不是删除其不确定性或补写一个确定答案。

## 5. A/B/C/R 证据层级、呈现策略与互斥决策

### 5.1 A-core

六项准入条件和全部确定释义门均通过；边界清楚、核心义稳定、精确匹配安全、没有未解决主要反例。
renderer 可以用陈述句给出一个有证据支持的核心释义，但仍不得给出当前文本的任务答案。

### 5.2 B-contextual

该表达确有解释价值，至少一个 sense 有支持，但存在不适合压缩成单一确定释义的性质：

- 多义或普通义/网络义并存；
- 语气、立场、讽刺、回收或引述显著改变解释；
- 只有在特定上下文中才使用为代称；
- surface 边界成立，但需要 context sense gate；
- 核心指称稳定，语用状态却不能在阶段一安全省略。

B 不是“质量较差的 A”，而是需要判断者结合当前文字选择解释的合法资源。B 证据卡必须：

- 列出所有达到证据门槛的主要解释，不只列最可能或最负面的一个；
- 为每个解释写明可观察的适用条件或上下文线索；
- 明示“需结合原文判断哪一种解释适用”；
- 不由词典编纂器或 task-blind selector 替判断者选择当前 occurrence 的 sense。

B 可以进入阶段一完整策略，但不能使用 A 的单一定义模板。

### 5.3 C-quarantine

候选是 fit 中可定位、可能有真实解释价值的表达，但当前不能可靠裁决：

- 标准形式、边界或形成机制不确定；
- 证据不足、来源相互冲突或仅有模型猜测；
- 可能是一次性创造，也可能是稳定用法；
- 变体关系尚未确认；
- 人工审核无法在不补充调查的情况下选择 B 或 R。

C 的 `quarantine` 是隔离**未经证实的断言**，不是把整个表达从资源中隐藏。C 证据卡必须：

- 明示“现有证据尚不能确定该表达的具体含义”；
- 写清未知点、证据冲突或调查限制；
- 只有某个候选解释已有独立支持时，才以“可能解释”列出；
- 没有受支持假设时只报告未决状态，禁止为了“有内容可展示”而生成释义。

C 进入完整证据库。只有表达边界本身已经确认、能够安全精确命中的 C 才生成阶段一不确定性卡；
边界仍未决或不连续匹配协议尚未冻结的 C 暂留审计平面。补充证据后应产生新决定，可升为 A/B
或降为 R，不覆盖历史记录。

### 5.4 R-reject

候选明确不满足资源对象要求，包括透明表达、通用辱骂、语法碎片、完整句、错误 substring、
完全无根据且没有可说明解释缺口的 sense、重复项或非 fit headword。R 记录必须保留原因，不能删除后
假装从未出现；R 不生成任何模型可见证据卡。

### 5.5 互斥决策顺序

对每个 `(mention, proposed sense)` 按以下顺序决定，避免 A/B/C/R 重叠：

1. 若不是合法语言单位，或不存在解释缺口：`R`，不呈现；
2. 若可能有解释价值，但含义/证据尚不可判：`C`；边界安全时按未决模板呈现，否则只留审计平面；
3. 若一个或多个含义成立但需要上下文 sense gate：`B`，按多解释模板呈现；
4. 只有六项条件和确定释义门全部通过：`A`，按单一释义模板呈现。

不得把“B 或 A”“先 A 后看”“模型高置信所以暂时 A”写入正式决定。需要调查时先 C；需要上下文
时明确 B；A 只表示当前已经满足全部门槛。层级在同一版本中互斥，但 B 可包含多个 sense，C 可包含
多个相互竞争的受支持 hypothesis；“内部有多个解释”不等于“同时属于多个层级”。

## 6. Span 边界规则

### 6.1 Raw text 与规范化视图分离

可为分析生成 Unicode、全半角、繁简、Latin lowercase、标点压缩或拼音视图，但必须保留
`normalized_index → raw_start/raw_end` 映射。最终 mention 一律写回 raw offsets，不得把规范化
后的字符串冒充原文 span。

### 6.2 最小语义充分原则

选择能独立承载特殊含义的最短 span：

```text
原文：女拳不行
拒绝候选：女拳不（R: fragment）
可另建候选：女拳
田园女权带坏了 → 田园女权（若整体具有独立 sense）
```

不能仅因短 span 也出现过，就覆盖长 span 的非组合义。

### 6.3 替换成立原则

把 span 替换成候选释义后，句子应基本保持预期含义和语法角色。若替换失败：

- span 过短时执行 `expand`；
- span 带入无关成分时执行 `trim`；
- 整个解释只对当前句修辞成立时执行 `reject` 或 `defer`。

### 6.4 功能词排除原则

否定词、程度副词、语气词、体标记和普通连接词通常不进入 span，除非整个组合已有证据表明
词汇化。因此 `女拳不`、`女拳都`、`些女拳` 这些候选本身属于语义碎片，应判为 R。若原文中
还存在完整表达 `女拳`，应另建 mention 重新裁决，而不是把碎片候选直接修成 B 或 A。

### 6.5 嵌套原则

- 短 span 与长 span 表示同一 sense：保留最小自足 span；
- 长 span 有独立非组合义：保留长 span；
- 两个 span 各有独立 sense：允许两个 mention，但必须分别给出边界和证据；
- 无法确定长短关系：进入 C，不得依分数自动选择。

### 6.6 Substring projection 禁止原则

不能把父短语或整句的含义投射给子串：

```text
easy girl 具有短语义 ≠ easy 单独具有该义
全国女性中出现连续字符“国女” ≠ 出现术语“国女”
```

阶段一 A/B/C 证据卡均不得采用裸 substring。匹配必须经过冻结的边界门，并优先最长的语义自足
span。如果某 surface 经常嵌入普通长词而造成不可消除的假命中，它不能进入模型可见视图；不能
因为它是 B 或 C 就放宽 span 安全要求。

### 6.7 多次出现原则

同一 surface 在一句中出现多次时，每次 occurrence 单独记录：

```text
surface, occurrence_ordinal, start, end
```

不能只保存字符串后默认所有位置含义相同。

### 6.8 多义 occurrence 原则

只有当前 occurrence 使用特殊 sense 时才标对应 mention。不能因为一个字符串在别处是网络语，
就把所有 occurrence 都标为相同 sense。若阶段一无法用确定性边界/形式规则区分普通义和特殊义，
该 surface 至少为 B，不能为 A；B 卡应同时列出已获支持的普通义和特殊义，让判断者结合当前原文
选择，而不是由上游静默选择特殊义。

### 6.9 引述、讨论与回收用法

引号不是自动排除规则，但引述、词语讨论、群体内自称或回收用法可能改变语用。核心义完全相同
也必须单独记录 occurrence；若这种差异会影响单一定义的安全性，则归 B，并在适用限制中说明差异。

### 6.10 不连续表达

默认只呈现连续 span。不连续编码可在审计平面记录 `segments` 和 `envelope`，但在没有独立协议
前不得强行把中间大量无关字符并入连续词条；可以留在 C 证据库，但不得生成模型可见卡。

## 7. 人工操作与原因代码

### 7.1 六种人工操作

| 操作 | 使用条件 | 必需输出 |
|---|---|---|
| `accept` | 原边界正确，候选确有解释价值 | 精确 occurrence、候选 entry/sense、暂定层级 |
| `trim` | 候选含功能词、修饰语或句法附着 | 修订后的更短 raw span 与原因 |
| `expand` | 候选把短语义错误投给子串 | 修订后的完整 raw span 与原因 |
| `split` | 一个候选包住两个以上独立表达 | 每个新 mention 的 raw span 与独立决定 |
| `reject` | 明确不属于资源对象 | R 原因代码，不生成 entry/sense |
| `defer` | 可能有解释价值但证据/边界/变体未决 | B 或 C、卡片可见状态，以及需要补充的具体证据 |

操作和 evidence tier 是两个不同字段。`trim` 适用于外围标点等不改变候选性质的边界误差；像
`女拳不` 这种带入句法成分的语义碎片应直接 `reject → R`。如果原文中另有完整的 `女拳`，应
新增 mention，并对新 mention 重新决定 A/B/C/R。

### 7.2 标准原因代码

| 代码 | 含义 | 默认去向 |
|---|---|---|
| `transparent` | 普通字面或常规组合已足够理解 | R |
| `ordinary_identity_or_name` | 普通身份词、人名、地名或称谓，无特殊 sense | R |
| `generic_insult` | 只使用普通辱骂或负面词义 | R |
| `fragment` | 非自足 n-gram、分词或语义碎片 | R |
| `function_word_attached` | 带入否定、程度、语气等成分，候选本身不自足 | R；完整子项另建 mention |
| `sentence_level` | 完整句、分句或临时修辞 | R 或 split |
| `wrong_boundary` | span 过长、过短或 occurrence 位置错误 | trim/expand |
| `substring_projection` | 父短语/上下文意义被错误投射给子串 | R 或 expand |
| `unsupported_sense` | 无证据支持提出的具体含义 | C/R |
| `one_off_creation` | 只在当前句临时成立，无法迁移 | C/R |
| `ambiguous_surface` | 普通义/特殊义或多个 sense 无法安全区分 | B |
| `context_polysemy` | 解释依赖当前上下文 sense | B |
| `quoted_or_reclaimed` | 引述、讨论或回收用法改变语用 | B |
| `evidence_conflict` | 独立证据相互冲突 | C |
| `variant_unresolved` | headword 与变体关系未证实 | C |
| `non_contiguous_unresolved` | 需要尚未冻结的不连续 span 协议 | C |
| `label_derived` | 候选或释义来自被禁止的任务标注路径 | R |
| `not_fit_attested` | 正式 headword 未在 fit raw text 出现 | R |
| `duplicate` | 与已裁决 mention/entry/sense 重复 | R/merge |
| `no_neutral_gloss` | 无法写出非决策性的核心词义 | R/C |

审核者不得只写“感觉不像词”“模型不确定”或一个总分；必须选择操作、层级和可审计原因。

## 8. A/B/C 分层证据要求

### 8.1 Fit context pack

分层和撰写证据卡前，为每个候选收集：

- 所有 fit occurrences 及 raw offsets；
- 彼此独立的 fit record 数；
- surface/canonical 候选和形成机制；
- 同一 surface 的普通义、相反例和潜在替代义；
- 候选生成来源，仅供编纂审计，不作为真值。

严禁加入被禁止的任务字段、原词典类别、dev/test 内容或下游模型预测。

### 8.2 三条允许的 A-core 证据路径

满足任意一条只是通过 `E_support`，仍需满足其他五项与确定释义门。

#### E0：确定性形式转换

- 至少一个 fit mention；
- surface 到 canonical form 的转换明确、可复核且没有合理替代解码；
- 替换检查通过；
- 人工核对通过。

适用于清楚的缩写、全半角、拆分、字符替换或音形编码。Web 可选，但模型单独猜测不属于
“确定性”。E0 是确定性单例的专用保守路径；非确定性单例不能借 E0 豁免，必须满足 E2。

#### E1：稳定词汇化表达

- 至少两个不同 fit records 中存在一致 sense；
- 至少一个权威辞书、学术资源或其他高质量直接来源；
- 没有主要反例或来源冲突；
- 人工确认核心释义可迁移。

#### E2：罕见或社区表达

- 至少一个 fit mention；
- 至少两个内容和 lineage 独立的外部来源，其中至少一个直接解释或展示目标用法；
- 镜像转载、互相抄录和同一原始帖的转载不算独立；
- 搜索摘要不能单独计为来源；
- 人工核对通过。

### 8.3 B-contextual 的证据门

B 不是容纳“有点像术语”的宽松桶。要生成 B 证据卡，必须同时满足：

1. 至少一个 fit mention 的精确边界可重放，且候选是语义自足单位并存在解释缺口；
2. 至少一个核心 sense 得到直接证据支持；
3. 使其不能成为 A 的上下文依赖、多义、引述/回收差异或普通义反例也有实际证据；
4. 卡中列出的每个主要解释分别完成 claim–evidence 对齐；
5. 卡中适用条件是原文可观察线索，不是任务标签、模型预测或编纂者替当前 occurrence 作出的选择。

单个 sense 的支持可沿 E0/E1/E2 核查；E1 中“没有主要反例”解释为该 sense 自身的核心定义没有
冲突，不要求整个 surface 只有一个 sense。若某个竞争解释只有 LLM 猜测而没有独立支持，不得把它
写入 B 卡；若它又构成无法排除的关键不确定性，应将整个候选放 C，而不是只展示较方便的解释。

### 8.4 C-quarantine 的证据门

C 允许“答案未定”，但不允许把明确噪声当作不确定术语。进入 C 至少要求：

1. fit 中有可重放 occurrence，候选有成为完整表达的合理边界，而非明确的碎片、整句或 substring
   误命中；模型可见 C 还必须已有精确、安全的最终边界；
2. 人工确认存在合理的解释缺口，且不能直接按透明词或通用辱骂判 R；
3. 记录已经检查的 fit contexts、支持/反驳材料和仍未解决的具体问题；
4. 不把模型自报、搜索摘要、单个无来源说法当作候选释义证据；
5. 只有得到直接或部分独立支持的 hypothesis 才能显示，并明确标为“可能”；没有此类支持时，
   `参考信息` 只写“具体含义尚不能确定”和未知原因。

C 的信息价值是告诉判断者“这里存在一个尚未可靠解码的表达，以及我们确切知道哪里不确定”，
不是给一个低置信度的确定释义。若连表达边界都未确认，C 只保存在审计平面，不生成卡。

### 8.5 单例规则

只有一个 fit occurrence 的候选：

- 明确满足 E0 时可以继续申请 A；
- 非确定性候选只有满足 E2 且无替代 sense 时才可申请 A；
- 核心义与上下文限制均有独立支持时可以为 B，并按多解释模板呈现；
- 只有一个社区帖子、一个模型解释或一个模糊搜索结果时，最多为 C，且无独立支持的具体解释不得
  出现在模型可见卡中；
- 不得因词条数量不足降低单例门槛。

### 8.6 Claim–evidence 对齐

至少拆分并核查：

```text
C1 surface ↔ canonical form
C2 核心词义
C3 形成机制
C4 适用范围或边界
C5 主要替代义/反例
```

每条证据标记 `support / refute / qualify / background` 和 `direct / partial / context_only`。
背景相关不等于直接支持，关联含义不等于词典义。A 的核心释义、B 的每个候选解释和适用条件、
C 的每个可见 hypothesis 与不确定性说明都必须逐项对齐；层级越不确定，越不能降低单条 claim 的
诚实表达要求。

## 9. 人工复核与疑难项处理

### 9.1 人工复核要求

每个拟进入模型可见 A/B/C 证据卡的 sense 或 hypothesis set 都必须经过人工检查。审核时可以看到
raw fit context、候选 evidence 和卡片草案，但不得看到：

- 被禁止的任务标注；
- 下游模型预测；
- 候选的模型身份、投票数量或自动 confidence；
- 以类别相关性计算的任何排序信息。

审核记录必须包含：边界、entry/sense 归并、A/B/C/R、模型可见状态、证据路径、卡片正文、主要
反例和原因代码。B 还要记录是否覆盖所有受支持主要解释；C 还要记录哪些 hypothesis 可以显示、
哪些只能留在内部调查记录。

### 9.2 疑难项类型

- span 边界不确定；
- entry/variant 归并关系不确定；
- sense 数量或适用 occurrence 不确定；
- 核心释义存在竞争解释；
- A/B/C/R 层级难以确定；
- 证据独立性或充分性难以确认；
- 是否含决策性措辞难以确认。

### 9.3 处理规则

- 任一未解决疑难项都阻止 A 的确定释义；
- 必须基于冻结的 evidence pack 作出并保存书面决定；
- 不采用多数模型投票、平均 confidence 或“先发布再观察”；
- 证据仍不足时降 C；sense 成立但需要上下文时降 B；B/C 卡必须把限制显式带给判断者；
- 后续补证据须产生新决定记录，不覆盖原决定。

### 9.4 发布前分层语义抽检

全量模型可见 A/B/C 卡完成人工复核后，按层级抽检：

- A：对至少 60 个随机 `sense-context` 对作盲化替换检查；A 少于 60 时全量检查；
- B：随机检查至少 30 个 `card-context` 对；B 少于 30 时全量检查，确认主要解释完整、条件清楚，
  且卡片没有替当前文本选 sense；
- C：随机检查至少 30 个 `card-context` 对；C 少于 30 时全量检查，确认不确定性如实呈现，所有可见
  hypothesis 均有支持，且没有暗示确定答案。

人工同时检查是否误命中 substring、是否遗漏主要替代义、是否加入无证据内容。发现实质错误时，
必须重开同一生成、分层或 rendering 路线的全部条目，不能只修抽中的一条。

## 14. 阶段一的完整证据呈现与实验条件

### 14.1 默认资源视图

完整审计库保存 `A ∪ B ∪ C ∪ R`。阶段一默认模型可见视图为：

```text
L_policy = A + B + C_visible
```

其中 `C_visible` 指表达边界已确认、能够安全精确匹配的 C；其余 C 仍保存在审计库，但不生成卡。
R 永不生成卡。由此，“没有向判断者提供某个候选”只可能因为它是 R，或因为连安全命中的表达边界
都尚未确认，而不能只因为它不够资格成为 A。

renderer 使用统一字段，但按内部层级采用不同内容策略：

```text
# A：确定释义
表达：<当前实际命中的 surface>
参考信息：<一个有证据支持、可迁移的核心释义>
适用限制：<只说明词义，不推断当前句子的立场或结论>

# B：上下文多解释
表达：<当前实际命中的 surface>
参考信息：<所有受支持的主要解释，以及各自的可观察适用条件>
适用限制：<需由判断者结合当前原文选择适用解释；上游不代选>

# C：未决信息
表达：<当前实际命中的 surface>
参考信息：<具体含义尚不能确定；仅在有支持时列出“可能解释”和证据限制>
适用限制：<只能视作不确定参考，不能据此单独得出当前文本结论>
```

上例中的 `A/B/C` 注释只说明本手册逻辑，实际输出不显示层级字母。判断者应看到信息本身的确定
程度，却不应看到内部评级、来源数量或审核过程，以免把层级误当成任务先验。

### 14.2 固定的检索与边界约束

- 不使用 semantic-only retrieval；
- 只对当前文本中的精确边界命中生成卡；
- 不把裸 substring 当作 exact hit；
- 重叠时优先最长的语义自足且已审核 span；
- 不显示完整 evidence、内部 `usage_notes`、审核备注或未命中的 variant 列表；
- 同一 surface 多义时整体走 B，呈现全部受支持解释，不由上游自动选 sense；
- C 无受支持 hypothesis 时只说明未决，不补写猜测；
- A-core 很小或命中率低时如实报告，不降低 A 门槛，也不把 R 提升为 B/C 补数量。

### 14.3 阶段一条件与因果比较

为回答“只给确定释义”和“给完整但分层的不确定信息”之间的差异，至少冻结以下条件：

| 条件 | 模型可见内容 | 作用 |
|---|---|---|
| `L_A` | 只显示精确命中的 A 确定释义卡 | 高精度基线，也是原 A-only 策略的保留消融 |
| `L_AB` | 显示 A 确定释义卡与 B 多解释卡 | 单独估计加入上下文多义信息的增量 |
| `L_policy` | 显示 A、B 和 `C_visible` 分层卡 | 阶段一默认完整策略，检验“把不确定信息交给判断者” |
| `PL_policy` | 与 `L_policy` 命中成员完全相同的非语义安慰剂卡 | 控制额外文本、注意力和“这里有词典命中”的提示效应 |

`PL_policy` 必须逐 mention 匹配卡片数量、顺序、统一字段、备选项数量和预注册的 token-length band；
内容不得解码该表达，也不得携带任务线索。它不能另抽一组更容易或更难的词，否则无法把差异归因
于真实参考信息。

主要报告 `L_policy`，同时报告 `L_A → L_AB → L_policy` 的覆盖增量，以及按 A/B/C 来源拆分的有益
变化、有害变化和无变化。结果分析与词典编纂隔离：这些下游结果不得反过来作为候选纳入、层级
提升或释义修改的证据。

这一边界只规定未来接口和实验意图；本 Step 1 不修改现有 retrieval、renderer、control、schema
或任何实验产物。
