# 已确认人工审核规则与本轮确认范围

日期：2026-09-16。作者：assistant。本文是既有冻结规则及明确增补的阅读汇总，原文来源见末尾。新模型任务说明及新增记录项为本轮定稿待确认；本文不声称已经获得该逐字确认。

用户本轮已经认可建议方向，并要求查看最终文本后确认。该方向认可不等于逐字接受本目录的新文本，也不产生任何新材料标签、线上人工确认或 GPU 执行授权。

**适用与优先关系。** 基础为 evidence-applicability-annotation-policy/v2；攻击严重度采用 evidence-attack-severity-policy/v1，hate 映射采用后来已确认的 evidence-severity-hate-default-mapping/v1。后者已替代严重度规则中“hate 与严重度独立生成”的条款。group 还应用个人辱骂 others 增补、种族与个人辱骂合并规则，以及其后同一黑人对象的限制；不能只读较早的宽泛合并句。

这些政策原有适用范围和历史身份保留。既有分析参考以其自身冻结来源和明确限定的裁决为准，不能把规则级确认、默认映射或某次个案裁决扩展成覆盖全部历史记录的规则。

**审核事实。** 先根据可见文本确定对象、命题、作者立场与证据片段，再作判断。区分当前作者、被引用者、被反驳者；区分具体行为批评、人格贬损和对群体的泛化。不能用词典、召回示例、原 Gold 或模型解释补造上文、对象身份或作者态度。

**攻击严重度与当前默认 hate。**

| 严重度 | 已确认锚点 | 默认 hate／新模型输出对应 |
|---|---|---|
| 0 | 无作者认可的攻击；中性讨论、普通赞同、单纯反驳攻击且没有独立贬损或伤害主张 | non-hate／无 |
| 1 | 针对人的轻蔑、挖苦或轻度负面概括，尚未达到更强内容 | hate／有 |
| 2 | 直接人格羞辱、侮辱性归类或明显的群体污名概括 | hate／有 |
| 3 | 认定对象天生低等、不配作为人，或主张因身份剥夺平等参与和基本权利 | hate／有 |
| 4 | 合理化、赞许针对人的身体伤害，或直接威胁、鼓动此类伤害 | hate／有 |
| null | 证据不足或边界待定，无法可靠选择活动严重度 | 无法由严重度产生新 hate 映射；不能当作 0／无 |

量表是有序分级，不测标注者的冒犯感、作者情绪激烈程度或模型置信度。4 不表示 2 的两倍。只有活动严重度参与映射，候选分不能替代待定值；未赋严重度不能根据旧 hate 反推分数。null 不删除已有独立 hate 裁决，但不能假称已经有新的严重度映射。

映射若与旧人工 hate 不同，保留旧裁决与政策，当前映射视图按新默认生成并展示差异，不为保住旧 hate 而改严重度。后来的明确个案／分析参考裁决按其授权范围单独保存；暂行映射没有未经确认的隐含例外。

**共同判定边界。**

1. 已成立的轻度人格贬评或个人辱骂可以计入攻击，不要求攻击对象带有群体身份，不增设“只有受保护群体才算”的限制。
2. 单纯行为、事件或观点批评不自动等于攻击；是否带有人格侮辱、身份贬损或伤害主张，须根据实际命题判断。玩笑、粗口、情绪、标点和表情不能单独决定等级。
3. 中性身份提及、释义、自述、引用均不因出现辱称而自动升级；引用／转述须辨别作者认可关系。明确反驳的攻击不算当前作者实施的攻击。
4. 反仇恨表达中独立成立的个人辱骂或其他攻击仍需计入；不能由反对态度覆盖整句的其他攻击。
5. 多项作者认可的攻击并存时，句级严重度取有证据支持的最高等级，保留对应对象和形式；最高分不能传播给所有被提到的对象。
6. 缺上文本身不足以自动判待定；应指出缺失的信息如何影响标签。若有文本依据的合理解释会产生不同答案且无法消歧，保留未决；不能默认 non-hate，也不能凭无依据的猜测制造不确定性。
7. 机构、制度、资本等抽象对象与其成员分开判断，不能自动改写为具体人群。纯机构侮辱的未明确边界仍保留，不能从本轮主材料暂不采用推导它一律 non-hate。
8. 一个任务未决不阻止另一个已明确任务的裁决；多个合理解释若都导向同一任务标签，可以为该任务裁决并保留解释不确定性。

**词典、示例及适用关系的既有规则。**

- 定义本身的质量、该义项在具体来源位置是否适用、是否适用于当前查询，分别审核。单位是具体义项与出现位置；定义合理不等于每处命中都合理。
- 示例答案先按示例自身文本及任务规则审核；答案可靠性与对当前查询的适用性分开。已确认的同身份、同规则示例可以引用复用，新的查询关系仍须单独判断。
- 查询—示例关系分别记录“词义／话题关联”和“判断规则关联”，各使用 direct、partial、none、unclear，即直接、部分、无、不明，附对应片段。
- 另记录示例是否引入不适配词典及其来源边；这不能自动变成“示例整体无用”。
- 词典问题标记可多选：义项适配、子串误匹配、错义、定义过窄、不确定、未进入实际提示。来源存在不等于内容已呈现。
- 同词示例可能错义；跨话题示例可能在反泛化或立场规则上适用。资料正确、关系适用、模型实际使用、是否改善任务，不能互相代替。
- 人工认为无关或有问题只提出待检验解释；不能据此直接记为有害，也不能用模型输出反向决定材料适用性。

**group 的现行规则。** 此字段保留在审核层，不是本轮新模型需要输出的任务。

- 类别为 Racism、Region、LGBTQ、Sexism、others；对实际参与评价、辩护或攻击的人群身份／社会角色判类，而不是枚举所有出现的身份词。非仇恨表达也可有非空 group。
- 明确的其他身份／角色，在能排除四个专门类别时归 others；异性恋这一性取向属性本身归 others，不自动归 LGBTQ 或 Sexism。多重身份只记录实际参与评价的维度。
- 职业、宗教、年龄、社群、临时角色等不要求长期稳定，但必须实际作为评价单位。单纯地点或身份背景不自动赋类；机构本身和成员身份不互相替换。
- 后续增补规定：已经成立的个人辱骂通常计入 others，即使未按群体身份评价。单纯提人或行为批评不因此加 others；纯群体攻击也不自动再加个人辱骂项。
- 最新合并限制：受辱者被文本确认是黑人，且种族攻击与个人辱骂指向同一人时，个人辱骂这一项不另加 others。若对象不同或没有同一黑人对象的依据，不能仅凭共现删除 others，也不自动扩展到所有族群。
- 独立成立的政治身份等仍可贡献 others；其他明确类别继续保留。上述合并不消除攻击，也不改变严重度及 hate。
- 多对象的完整类别取并集；[] 表示确认无适用类别，null 表示会影响完整集合的未决。不能把专门类别不确定性塞进 others，也不能用已知的部分集合冒充完整结论。

**来源与确认。** 继续使用 AI 起草、用户核对的方式，不新增人类必须在 AI 之前独立作答的门槛。规则级接受、单字段裁决、整批采纳分别保留来源，不能互相充当；不把 AI 个案归纳升级为已确认通则。原标签、审核标签、同规则纠错和政策变化分别记录，旧结果不被新规则回写。

**本轮新增整理，待随新文本确认。** 在新材料中单列词面重合，并明确记录“哪项信息作用于查询哪个成分／判题环节”；这些来自本轮已获方向认可的建议，不冒充旧冻结中已有的独立字段。主材料仅采用任务参考已解决、适用关系能够支持预定比较的材料；待定不强行编码为无攻击或不适用。具体材料、字段 schema 和执行矩阵仍需单独物化。
