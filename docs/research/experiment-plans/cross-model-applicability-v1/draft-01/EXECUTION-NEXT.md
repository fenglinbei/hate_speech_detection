# CPU交付后的实施边界

当前只有设计与首批可审核小样；不是GPU执行包。`eligible_for_GPU=false`，无绑定、队列、自动轮询、模型forward或模型预测。本包不包含能够加载模型运行评分的入口。

下一步先处理用户对S1–S6及24项材料／120条关系的反馈。修改形成draft-02等独立版本，不覆盖本稿；采纳单独记录精确材料、字段、文本哈希及AI作者身份。材料审核通过不自动等于GPU数值资格。

随后扩充开发家族并处理当前共享构造依赖。初始预算四家族、16条查询、每查询24条件，只是规划规模；如果四格或依赖隔离无法成立，应报告缺格／依赖，不强行凑足“独立家族”。确认集仍需另外建设和冻结。

执行准备另版实现模型适配，绑定本地权重及实现哈希、精度、模板、设备和输入。GLM需要核查本地旧实现与运行环境的兼容性，且不能静默换成不同转换权重或新版模板。CPU token边界通过不替代前向、输出遵从性、重复／padding等必要数值检查。

未来资格检查覆盖实际新长度、batch和设备安排，异常停止并保留记录，不通过改变容差获得合格。实际显存和吞吐测量后再给用卡及壁钟时间；本轮没有启动该测量。

旧材料新两模型科学输入312项；本稿新材料八查询×24条件×三模型为576项。合计888个未来科学prompt-only前向，工程资格、必要桥接、格式生成另计。若扩至原计划四家族，则新材料1152项、连同旧材料1464项。条件数不代表统计独立样本数。

科学分析只在各模型资格、原始评分封存和资源释放之后加入人工参考。开发报告保留全部负结果和模型差异；确认前另行固定有限主假设、阈值、样本量和停止规则。内部候选、patch或MLP34迁移均未开始。
