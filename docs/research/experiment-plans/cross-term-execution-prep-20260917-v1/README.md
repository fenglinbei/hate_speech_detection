# 下一步：新评分器的运行准备与数值验收

本准备包绑定已确认的 [跨词项材料与输入设计](../cross-term-joint-v1/frozen-01/README.md)，使用完全相同的120个输入和252项表达式。当前完成输入隔离、读数/表达式CPU参考算术及验收计划；尚未绑定GPU运行实现、权重清单、环境和分配，不是已经可执行或验收通过的运行冻结。

## 实际运行要回答什么

固定查询和同一示例包，比较真实释义L、形式说明N与空词典槽。先看具体输入改变造成的分数差，再分别看是否跨过正确分类阈值。词典交互按同一词典差值相对无示例条件计算。A/B保留整包诊断，不按D规则关系值分组宣称适用性因果效应。

这些材料属于开发校准。本轮不设置任意的连续分数“有效”门槛，不用数值可分辨冒充实际重要性；功能修复明确要求对照数值解决且错误、处理数值解决且正确。独立确认的最小重要效应与不确定性方法留待确认协议在见到确认结果前登记。

## 已具体化的输入与工程计划

- model-inputs.jsonl：120条完整输入，只有正文、示例答案、token及身份信息，没有查询答案、严重度、关系评级或审核解释。
- analysis-plan.json：查询参考、家族、252项表达式和汇总方式，评分阶段禁止读取。
- next_token_math.py：纯CPU参考算术，从同一完整词表向量取有／无logits；覆盖合法输出质量、平局、未资格化、误差带和物理项合并后的传播。它不是模型forward执行器。
- qualification-plan.json：单GPU、batch=1、FP32 eager、无KV缓存；同120输入进行基准、重复、左右padding和请求逆序五次，共600次prompt-only forward。资格封存后再正式评分120次，共720次forward、1440个候选值；12条自由生成诊断另计。

误差界在工程阶段按预先给定公式生成；当前为null。所有输入均覆盖，不借用旧Q01数值资格。重复与请求逆序要求完全一致；padding最大margin差不超过0.001；b=max(0.000001,2×工程最大margin差)。这是本轮新拟定的工程包络，既不是实际重要性门槛，也不是统计置信区间。任何失败先停下核查，不能见到结果后放宽标准。

数值任务仍须绑定具体模型权重、运行实现与GPU UUID。本计划只限定单卡单请求实现，不能自动扩展到多卡、batch>1、prefix cache或其他dtype。未加载模型权重或启动GPU任务。

## 检查

使用普通Python运行 validate_preparation.py，验证完整输入字节、元数据隔离、表达式、预算和CPU算术；测试包括真实252项系数在合成分数上的独立60位Decimal复算。合成读数不是模型输出，不产生实验结论。
