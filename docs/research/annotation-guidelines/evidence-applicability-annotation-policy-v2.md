## 2. AI 预填、人类核对的四类信息

1. **谁在表达什么立场？** 区分当前作者、被引用者、被反驳者；记录赞同、否定、反驳、转述、反讽、自述或无法判断及其措辞依据。
2. **实际在评价谁/什么？** 分开记说话者、评价对象、引文中的对象、普通背景提及；身份出现不等于成为攻击对象。
3. **负面判断落在哪里？** 是对可指认行为的批评、对个体的辱骂，还是由个体/事件扩大到群体的贬损或排斥？可以同时记录多种表达。
4. **本句能支持到哪一步？** 保存原文片段与缺失信息。缺上文不能靠召回示例、词典、原 Gold 或模型解释补造。

上述问题用于组织事实字段，不要求人工逐题写段落。AI 预填立场、对象类型、表达类型、证据高亮与短说明；人类直接核对或改选。默认展开 hate、group 及关键证据，其余事实按需展开。一个任务可以已解决，另一个仍未决。

## 3. hate：攻击、冒犯与立场

以下为本稿建议采用的规则；其中“保留未决”也是可执行的规则，不要求所有文本都得到二元硬标签。

| 表达类型 | 判定方法 | 不足时如何处理 |
| --- | --- | --- |
| 作者明确赞同的群体贬损、歧视、排斥或去人化攻击 | 在实际目标和作者立场明确时支持 `hate`；记录指向及贬损片段 | 目标或赞同关系不明时保留未决 |
| 普通脏词、情绪感叹、玩笑或不礼貌表达 | 词面本身不足以判 hate；若只有感叹且无攻击命题，可支持 `non-hate` | 若已构成定向辱骂但是否纳入任务 hate 无统一依据，记 `policy_ambiguous` |
| 对具体行为、事件或观点的批评 | 不从负面评价直接推出 hate；若仅批评行为、未含侮辱/身份贬损/群体泛化，可支持 `non-hate` | 夹带定向侮辱时分开记录，按个体冒犯边界处理 |
| 对个人的侮辱、威胁或人格贬损 | 先记录攻击事实；不因目标是个人就自动判 non-hate，也不直接把所有个体冒犯并入 hate | 当前任务范围不足以确定时记 `policy_ambiguous`，裁决为 `null` |
| 从个体/个别事件推广到群体 | 检查是否把负面属性赋给群体；没有“都/所有”也可能是泛化，有这些词也未必是攻击 | 分清作者在实施泛化还是反对泛化 |
| 引用、转述 | 判断作者是否认可引文；引文含攻击词不足以判作者 hate | 单纯转述且立场可辨时按作者表达判断；归属不明且影响标签时记 `context_insufficient` |
| 否定、反驳、反仇恨 | 明确否定群体贬损，且没有另行发起攻击时，支持 `non-hate` | 反驳同时攻击另一对象时分别分析，不能由开头的反对态度覆盖后续攻击 |
| 反讽、反话 | 使用文本内反差、上下句关系等证据判断实际立场，不仅凭标点、表情或攻击词 | 多种合理解释导致不同标签且缺判别语境时，记 `context_insufficient` |
| 自述、群体内自称、词语释义 | 不从身份词或污名词出现直接认定攻击；看是否实际实施/认可贬损 | 身份和使用方式无法确认时不代入作者真实身份，保留未决 |
| 机构/组织及其成员 | 分开记“批评制度/服务”“侮辱机构”“攻击其成员群体”，不互相替换 | 纯机构侮辱的 hate 范围没有统一依据时记 `policy_ambiguous` |

对个人的表达若实际攻击其群体身份，按群体/身份攻击规则判断，不因目标仅一人而排除。上述明确 hate 规则以对象属于本版本已确认的任务攻击范围为前提；对象指代明确，但这类对象是否纳入任务本身未明确时，保留 `policy_ambiguous`。临时集合或机构成员不能仅因人数多就自动套用群体攻击规则；这也不新增“仅受保护群体”的限制。

混合表达按当前作者的全部有效表达分析：若至少一处满足本规则的明确 hate，句级 hate 可判 `hate`；被明确否定的引文不能仅因包含攻击命题而计入。不存在明确 hate，且仍有可能改变句级标签的未知部分时，保持 `null`，不能默认 `non-hate`。

本稿不拟设独立的 offensive 标签，也不把 `policy_ambiguous` 当成第三个模型类别。它是人审参考不可用的原因。

## 4. group：实际身份对象与类别范围

group 标注文本中实际作为评价、辩护或攻击对象的**人群身份或社会角色**。因某种身份评价一个人，也属于该身份对象；人数并非门槛。先确定对象及其身份在命题中的作用，再映射类别。

现有五类由四个专门类别 `Racism / Region / LGBTQ / Sexism` 和剩余类别 `others` 组成：

> 当文本明确以某种人群身份或社会角色为评价、辩护或攻击单位，且已确定本命题实际评价的身份或角色维度不能映射到四个专门类别时，group 归入 `others`。

明确提及某种身份不足以成立 group；身份只是背景，或仅描述某人的具体行为时，不因身份词出现赋类。对群体的正面评价、非仇恨辩护也适用本定义。作者明确辩护的类比群体可以是实际对象，不能仅因承担类比功能就排除。

### 4.1 已确认的对象范围

| 对象或表达 | 规则 |
| --- | --- |
| 按“异性恋”这一性取向身份评价或辩护人群 | `others`；异性恋这一属性本身不映射为 LGBTQ，也不映射为 Sexism |
| 职业、宗教信仰、年龄、社会阶层、组织成员、兴趣社群等身份或角色 | 明确作为对象，且能排除四个专门类别时，归 `others` |
| 游客、乘客、观众等角色 | 不要求群体长期稳定；只有以角色为评价单位时才归类 |
| 多重身份 | 只映射实际参与评价的身份；同一人可以有异性恋与跨性别等多重属性，按跨性别身份评价时应考虑 LGBTQ，不能用异性恋属性抹去其他实际身份对象 |
| 只有个人目标，未以群体身份或角色评价 | group 为 `[]`；个人辱骂是否 hate 仍按父规则独立裁决 |
| 只有机构、企业、平台、政府本身，未指向成员身份 | group 为 `[]`；机构冒犯是否 hate 仍按父规则独立裁决 |
| 机构名可能转喻成员、经营者或居民，且不同读法改变 group | 保留 `null`，记录需区分的对象及语境；不能机械套用机构 `[]` |
| 只因共同在场或某次行为指认的几个人 | 人数多不自动构成身份对象；若只评价具体行为，无其他身份对象，则为 `[]` |
| 身份、地名等仅为背景；对象为地点、物品、事件或抽象观点 | 无其他实际人群身份对象时为 `[]` |
| 抽象讨论“性取向”“群体偏见”等概念 | 不自动枚举所有可能的性取向或群体类别；结合文本实际具体对象判断 |
| 对象属于 Racism 还是 Region 等专门类别仍无法确定 | 保留 `null`；`others` 不用于容纳类别选择的不确定性 |

本版不规定所有国籍、民族或交叠身份的唯一映射。剩余类别的判定要求能排除四个专门类别，不能把尚未解决的专门类别边界整体移入 others。

### 4.2 类别、无类别与未决

1. 确认文本中是否存在作为评价、辩护或攻击单位的人群身份／社会角色。指代可以隐含，但必须有文本内可核对的依据；不能补造上文或用召回示例代替上文。
2. 若判断充分，确实没有这种对象，选 `[]`。有身份词但仅作背景也可为 `[]`。
3. 对每个实际身份对象，能映射专门类别则取该类别；已排除四个专门类别则取 `others`。
4. 对多个实际对象取类别并集。多个群体映到同一个类别时去重。
5. 若文本内证据支持的合理读法中，某个实际对象或类别尚未确定，且会改变完整类别集合，正式 group 仍为 `null`，保留已知部分及候选理由。不能用部分集合、`others` 或 `[]` 替代未决，也不能仅凭没有文本依据的猜测制造未决。

`others` 表示已确认的其他身份／角色类别，`[]` 表示已确认无实际群体身份对象，`null` 表示仍有影响答案的不确定性。三者不随 hate 标签自动变化。

以上范围是本版人工参考的语义规则，不证明原数据已完整采用相同范围。原标注未覆盖与同口径漏标必须区分；规则变化不能汇报成源数据误标。

## 5. 原四元组、原投影与新句级参考

原四元组为 `target / argument / targeted_group / hateful`。对合法、完整的冻结四元组，原投影保持：

```text
original_hate = "hate" if any(tuple.hateful == "hate") else "non-hate"
original_group = union(all tuple.targeted_group) - {"non-hate"}
group canonical order = Racism, Region, LGBTQ, Sexism, others
```

保留具体 group 与 `hateful=non-hate` 的合法组合；不先按 hateful 过滤，不只取第一个 tuple。缺失/非法四元组不自动投影为 non-hate 或空集合。

本轮审核形成**句级、按任务的独立覆盖层**。原四元组、原 projection、示例原答案、模型输入与原预测保持可追溯；审核不默认重写 target/argument 跨度或完整四元组。

原标签存在问题时，分别记录：原四元组本身的语义疑点、投影实现/数据适配疑点、句级目标遗漏、规则差异、缺上下文。确定性投影正确不证明源标签正确；人工不同意也不自动证明投影代码有错。

审核标签与原标签不一致，需要注明是**同规则下纠错**还是**规则口径变化**。后者不得汇报成源数据误标。审核 Gold 只用于对同一批已有预测作另一个参考下的评估；修改示例答案属于后续输入实验。

## 6. 未决、审核进度与裁决可用性

三个维度分别保存，不相互推导：

| 维度 | 值及用途 |
| --- | --- |
| 原标注审核状态 | `accepted`：认可；`suspected_error`：同一规则下有相反证据；`policy_ambiguous`：任务定义/映射冲突；`context_insufficient`：缺判别语境；`policy_changed`：group 在新规则下已裁决，差异来自规则变化 |
| 参考可用性 | `resolved / unresolved`；正式裁决值为合法标签/完整集合或 `null` |
| 提交进度 | `unreviewed / draft / confirmed`；确认“未决”只表示完成记录，不表示硬标签可用 |

`policy_changed` 仅用于本次 group 范围修订后的已解决裁决，正式 group 为完整集合（可为 `[]`），不能用于 hate、未决标签或冒充源数据错误。`policy_ambiguous` 仍表示规则疑问尚未解决，标签必须为 `null`。

多个问题同时存在时保存完整理由，选一个真正阻止当前任务裁决的主状态。原查询 Gold 尚未揭示时，“原标注审核状态”保持未填；材料核对步骤只记录人类基于 AI 初稿核对的判断及不确定原因，不能提前默认 accepted。

任何 `resolved` 裁决都必须有明确任务、文本哈希、规则版本、人工依据及裁决人。`suspected_error` 本身不生成替代标签；只有后续人工裁决解决后才可成为可用覆盖层。未解决的政策冲突和上下文不足保持 `null`。同一人完成审核与裁决可以推进，须标 `single_review`；AI 意见不得获得 human 确认身份。

若多个合理解释导向不同标签，记录候选及各自证据；若它们均导向同一任务标签，可以为该任务裁决，同时保留解释不确定性。“缺上文”本身不足以自动置 null：应指出文本中哪处需要什么信息才能区分不同标签；优先用原因选项和原文点选记录，由 AI 预填短说明。不能让另一个未决任务阻止已经明确的任务，也不能由已决任务填充另一个任务。

正常记录不设人工长文本必填项。认可 AI 草稿、修改标签或确认未决，均可用选择题和证据选择完成；已有选项不足、选择“其他原因”时才补简短文字。依据标签、原文片段和最终字段可以自动合成报告，但要标明文字来源，不能把未采纳的 AI 说明记作人工观点。

## 7. 示例与词典：可靠性、适用性分开

AI 首先只基于示例自身文本和规则形成两个任务的标签初稿，保存后才在另一份对照记录中读取原答案，提出 `accepted / disputed / unknown` 的可靠性建议。人类可在同一示例卡核对正文、原答案、AI 草稿及差异，不必重新完成一次隐藏答案的独立填写。去重键至少包含来源数据身份、demo ID 和原文 SHA-256，同 ID 正文或任务答案冲突时停止合并。文本相同但 ID 不同仅记录 family，不静默合并原标注。已确认的同身份、同规则示例审核可引用复用，当前查询与它的关系仍单独审核。

每个查询—示例—任务关系分别记录：

- 词义/话题关联：`direct / partial / none / unclear`，附对应片段。
- 判断规则关联：同一组取值，另附立场、目标或推理规则的对应依据。
- 是否会引入不适配词典及其具体来源边；这不等于示例整体无用。

跨话题示例可能在反泛化等判断规则上适用；同词示例可能义项不适用。示例答案可靠、示例适用于当前查询、实际造成模型变化是三个不同结论。

词典审核单位为具体义项及具体出现位置，检查：词条解释自身有无问题、该义项是否适合来源文本、是否适用于当前查询、该来源是否实际进入相关条件提示。问题标记允许多选：`valid_sense / substring_mismatch / wrong_sense / overly_narrow_definition / uncertain / not_rendered`。一条合理定义仍可能在某个位置误命中。

位置使用原文 Unicode code point 的半开区间 `[start,end)`，验证 `raw_text[start:end] == raw_surface`，另存 normalized span 与映射。仅有 entry ID 不冒充已有精确命中边；重建必须绑定冻结词典和 matcher，聚合集合不符则记 `provenance_mismatch`，不替换旧输入。

人工认为“不相关/有问题”只形成候选解释；因果效用须由后续受控输入实验检验。本阶段不因为人审意见更改资源或运行模型。

## 8. 两步核对与 AI 来源记录

AI 初稿在人工开始前准备好。查询标签初稿只接收查询和规则；示例标签初稿只接收该示例和规则；资源适配草稿接收授权的查询/资源及来源信息。三者都不接收查询原 Gold、选样桶或实验预测。示例原答案的比较作为标签初稿之后的独立输出。只有最后的解释提案可以使用原查询 Gold 和轨迹，且单独存储。

| 人类步骤 | 页面开放内容 | 主要操作 |
| --- | --- | --- |
| 1：核对材料与 AI 初稿 | 查询、词典、示例及示例原答案；AI 标签、关系和依据高亮；隐藏查询原 Gold、选样桶和模型结果 | 核对当前对象，直接改选；“确认此项”同时确认已展示的两个任务与依据。全部必需材料记录已确认或明确未决后，保存不可覆盖的材料核对快照 |
| 2：对照原标注与结果 | 查询原 Gold、已有预测、差异表、单独的 AI 解释提案 | 选择原标注状态；保留/修订最终参考；选择后续用途；确认并继续 |

用户不必再手写四段资源概述、候选解释和替代解释。后两者由 AI 提案供选择或暂不采纳；只有拟用于后续实验的方案才需要进一步明确干预对象、保持项和替代解释。后续用途选择不自动放行实验。

服务器负责控制查询原 Gold、预测及完整条件提示的开放，也负责限制各类 AI 请求的输入字段；不能只在 UI 中隐藏已发出的数据。旧工作台的先人工后 AI 门槛属于另一模式，新模式使用独立附属记录层，旧会话和初读快照只读引用。

AI 原稿保持 `review_kind=ai_note`，生成、自动保存或载入均不增加人工完成数。人类明确确认后，另存 `review_kind=human_with_ai` 的最终记录，关联原稿及字段差异，标记 `adopted_unchanged / adopted_modified`；人工完全从空白填写时才可标 `human_authored`（仍须记录实际 AI 暴露）。

批量采纳只作用于人类主动勾选并核对的当前可见对象，保存明确的对象 ID 和版本清单；没有打开、没有明确纳入操作的 AI 草稿不随整例确认自动转成人审。已确认示例/义项通过版本引用复用，不伪造额外独立审核。

本模式形成 **AI 辅助人工裁决参考**，不宣称独立人工初判或盲审。此前见过 Gold、资源、轨迹、AI 的情况分项记录；隐藏功能不能消除历史暴露，旧 AI 意见也不能追溯标成未见结果的初稿。

## 9. 版本冻结、变更与重审

本版根据用户对 group 范围修订草案的明确接受冻结；未修改 hate 的语义边界。确认范围为：

1. 采用本稿明确的立场、目标、两任务独立、句级覆盖层，以及“AI 预填选择题 → 人类核对材料 → 对照原标注与结果”的流程；审核类型为 `human_with_ai`。
2. group 按 §4 确定身份／角色对象、others、纯个人及机构本身的 `[]`。hate 的个体／机构冒犯范围，以及仍无法唯一映射的国家／民族类别，继续保留未决；不因 group 归入 others 自动扩大 hate 的攻击范围。
3. 对仍存在会改变当前任务标签的未解决争议或关键语境缺失，可确认提交未决记录，但正式裁决保持 `null`。已完成同规则纠错裁决的 `suspected_error`，以及解释不唯一但任务标签一致的记录，可按 §6 登记为 `resolved`；后续参考依赖分析只使用已裁决任务。

确认时登记确认者、时间、完整规则文件 SHA-256 和明确接受的范围，再发布冻结版本。此稿的生成时间、Git 提交或 AI 自检通过均不是负责人确认。

冻结后的语义规则修订产生新版本，引用前版哈希并列出具体变化与受影响的审核记录 ID。改变 hate 的个体攻击范围时重审相关查询及示例的 hate；改变 group 对象/类别边界时重审相关 group；若变化适用于全体，则标记全体相关任务重审。重审以新记录 `supersedes` 关联旧记录，保留旧裁决和更正理由。

若另设“个体冒犯纳入/不纳入 hate”等规则分支，先命名、冻结适用范围，分别产生覆盖层及报告。不能看哪个分支使模型得分更高后只留下该分支。

## 10. 本次版本衔接

本次 group 对象定义适用于整个授权审核范围。32 个查询、280 个去重示例及 320 个查询—示例关系的 group 任务登记新规则核对范围；同一对象共享引用去重。现有确认、草稿、材料快照、暴露历史、作者身份与原始时间保留，迁移不代替人工确认。对象 ID 与案例 ID 清单见冻结回执及附属规则文件。

hate 判断、词典定义和语义适配不会仅因 group 政策换版自动作废。若人类另行改变原文解释、共同依据或其他任务判断，则按实际依赖版本重核。仅重核 group 时保留先前 hate 依据；修改共同字段或 hate 应显式重新打开。

`policy_changed` 将新口径下已裁决的 group 与同口径误标区分。导出按任务记录采用的政策与可用性；旧 group 不能在未经重核时当成新规则参考。此前已见过的结果不会伪装成未见；原材料快照保持不可覆盖。

本版没有重新生成 AI 标签，没有读取 reserve 正文，没有修改模型提示或执行输入实验。若今后按新口径改变示例答案或模型任务提示，应作为另一个明确登记的输入实验，不回写既有预测。
