# 选择题优先、AI 初稿、人类修订：精简审核设计 v1

日期：2026-09-08（Asia/Shanghai）。状态：**可行性评估及交互提案，尚未实现、未批量生成初稿、未冻结或部署**。承接用户在 case 3169 流程演示后提出的“尽量减少手写，先 AI 初稿、人类修改”要求。配套语义规则为[判定规则 draft.2](evidence-applicability-annotation-policy-v1.md)，[draft.1](evidence-applicability-annotation-policy-v1-draft1.md)作为原字节快照保留。

## 1. 结论与精简目标

可行，建议实施。常规记录可以不手写：AI 预填结构化选项、依据标签和原文高亮，人类核对后采纳、改选或保留未决。主要节省重复组织文字、抄写标签和重复审核共享资源的操作；实际阅读量仍由材料决定，不能提前承诺节省多少分钟或提高准确率。

流程改为两个面向人的步骤：**核对材料与 AI 初稿 → 对照原标注和结果，确认用途**。查询、资源、示例之间的后台来源分工继续保留，人不再反复完成“空白填写 → 保存 → 展开答案 → 再写一段”。

方法上，这会形成 `human_with_ai` 的裁决参考，不再产生独立人工初判。相关主观标注实验发现 AI 建议会改变人类标签分布，且没有在该实验中带来更快标注；这不证明本项目不能提效，但意味着“少打字”和“更可靠/更快”应分开验证。[Schroeder 等，ACL Findings 2025](https://aclanthology.org/2025.findings-acl.1323/)

## 2. 用户实际需要做什么

沿用既有三栏：左侧搜索、进度和案例队列；中间完整原文、资源和证据高亮；右侧 AI 预填的选择卡、修改入口和保存状态。异常项可以突出显示，完整材料仍可展开，不增加一套独立 UI。

**步骤 1：核对材料。** 先看查询标签卡，再看示例和词典表。每个对象都可直接改选，按一次“确认此项”记录最终字段与所采纳依据，无需逐字段再次勾“已检查”。原查询 Gold、模型预测、选样桶和含这些信息的 AI 解释此时隐藏；示例原答案和单独的 AI 核对意见可见。

示例的两个任务及其当前查询关系可以放在同一行/详情卡，共用一次显式确认，但底层仍保存各自记录。已确认的同身份示例标签显示“引用既有审核”，只核对新关系，不重填自身标签。词典定义自身可类似复用，当前位置和当前查询适配不能全局复用。

支持勾选当前可见、已核对的多行并“采纳所选 N 项”，不默认勾全、不按 AI 置信度自动采纳。操作绑定确切 ID、版本及展示字段；隐藏详情中的待审核判断须展示后才能纳入。一个整例按钮不能悄悄确认全部未看过的资源。展示/滚动日志只说明材料出现过，不证明人真正读懂。

所有必需材料记录均已明确确认（包括确认未决）后，保存材料快照，进入步骤 2。没有初稿、没有证据或来源核验缺失的对象继续显示待处理，可手动改选/明确未决；不填默认 non-hate 或空集合。

**步骤 2：对照结果。** 系统呈现原 Gold、已有预测及与审核参考的差异。人选择原标注状态和后续用途，必要时修订参考；材料快照保留。候选解释、替代解释和输入方案由另一份 AI 提案提供，可选择“采纳/修改/暂不采纳”，无须强制写两段机制分析。最后“确认并继续”进入下一例。

草稿沿用 5 秒延迟自动保存、手动保存、离开保护、revision 冲突恢复；更正已确认记录可以选择简短原因，原记录继续保留。机制方案在真正进入输入实验前再细化，不把它作为每条例行标注的写作作业。

## 3. 将哪些字段改成选择题

| 对象/字段 | 页面选项 | 手写要求 |
| --- | --- | --- |
| 查询/示例 hate | 仇恨 / 非仇恨 / 未决 | 无；AI 预选，人类可改 |
| 查询/示例 group | 五类多选；另有“无任务类别 `[]`”和“未决 `null`” | 无；三种模式互斥，部分确定集合不能当成最终完整集合 |
| 原标注状态（按任务） | 认可 / 同口径疑错 / 规则歧义 / 缺上下文 | 无；仅在原答案可见后出现 |
| 作者立场 | 赞同或实施 / 否定或反驳 / 转述 / 自述 / 反讽 / 不明 | AI 预填，折叠事实区，可多选并绑定片段 |
| 对象类型 | 群体 / 因群体身份评价个人 / 仅个人 / 机构 / 事件或观点或表达 / 无明确对象 / 不明 | AI 预填；多个对象分开选，原文点选指明对应 |
| 表达类型 | 群体泛化 / 身份贬损 / 个体辱骂 / 行为批评 / 引用反驳 / 普通提及或笑声 / 其他 | AI 预填，允许多选 |
| 判断依据 | 作者明确赞同 / 作者明确反对 / 无攻击命题 / 无群体评价目标 / 同词异义 / 目标遗漏 / 范围未定义等 | AI 预填标签和原文高亮；无需重写摘要 |
| 缺失信息 | 指代对象 / 作者立场 / 词义 / 被回复内容 / 任务范围 / 其他 | 优先选原因、点对应片段，核对 AI 所列候选解释 |
| 示例原答案可靠性（按任务） | 支持 / 不支持 / 未能判断 | 引用已确认的示例标签核对结论，不重复发问 |
| 查询—示例关系（按任务） | 词义/话题关联：直接 / 部分 / 无 / 不明；判断规则关联：同四选 | 对应片段由 AI 预填；可显式选择“两任务相同”，不能自动按 hate 复制 group |
| 词典定义自身 | 合理 / 过窄 / 有其他问题 / 未决 | 过窄/问题可用原因标签，补充可选 |
| 来源位置的义项适配 | 适配 / 错义 / 子串误命中 / 不明 | AI 建议、人类核对；历史 span 身份由程序校验 |
| 该义项对当前查询的适配 | 适配 / 不适配 / 不明 | 与来源位置分开选 |
| 后续用途 | 参考标签分析 / 输入对照候选 / 仅无 Gold 行为观察 / 先核验 / 暂缓 | 按任务记录；候选不等于实验获准或前置条件已满足 |
| 更正/暂缓原因 | 误选 / 新证据 / 规则更新 / 来源问题 / 关键语境缺失 / 暂无可区分解释 / 其他 | 选项可构成简短理由；只有“其他”且现有说明不足时补一句 |

来源 ID、文本/规则哈希、时间、revision、呈现条件、原答案差异、AI/人工差异由程序记录，不要求人填写。来源图、span、是否进入提示属于机器可核验事实，不能靠 AI 自信的文字代替验证。

常规及多数异常记录均可零手写。只有选项不能表达新的关键问题、需要新的对象说明/规则分支、或选择“其他原因”且 AI 说明也不适用时，才需要简短补充；不设最低字数。补充文字始终可用，避免选项把合理不同意见挤掉。

旧工作台强制的四段资源观察、候选解释与替代解释长文本不再必填。“与 AI 一致/不一致”由字段 diff 生成；摘要可由最终选项和证据自动合成。修改标签后，旧依据若冲突应提示更新，可通过改选原因或高亮完成，不能把旧 AI 理由无提示保留为新标签的支持。

## 4. AI 初稿先做什么，哪些内容不能提前混入

| AI 输出 | 可使用的输入 | 单独保存的内容 |
| --- | --- | --- |
| 查询标签初稿 | 查询正文、当前规则、两个任务的标签空间 | 标签/未决、事实选项、原文依据；不使用资源、原 Gold、选样桶或实验结果 |
| 去重示例标签初稿 | 示例自身正文、相同规则与任务 | 先保存自身判断；不读取示例原答案或关联查询标签 |
| 示例原答案对照 | 已保存的示例自身初稿、示例原答案及必要的原 tuple | 可靠性建议和差异原因；不覆盖自身初稿 |
| 词典与关系草稿 | 授权查询、示例正文、词典义项、经过核验的来源图；必要的标签初稿引用 | 定义问题、来源/查询适配、按任务的两种关联及对应片段；查询原 Gold 和实验预测仍不可见 |
| 结果解释提案 | 材料核对快照、原查询 Gold、实际轨迹 | 候选解释、替代解释、具体对照设想；只在步骤 2 开放 |

这里的分工由独立调用/明确输入白名单落实，不把整张含 `profile.conditions`、Gold 和选样信息的案例 JSON 直接送给“查询初稿”。即使模型相同，也不得带入前一阶段含答案/结果的对话历史；记录实际输入哈希及可见字段。旧 12 条 AI 初读和已经见过结果的聊天演示可作为后期意见，但不能改名为未见结果的标签初稿。

标签初稿输出结构化值，不只生成长文章再要求人摘录。每条依据绑定原文片段；字符位置做 Unicode code point 校验。AI 无法定位历史 matcher span 时标待核验，不能编造轨迹。自由文本中的不确定点可显示一行，详细说明折叠；不展示一个没有校准依据的“高置信度”徽章来代替核对。

模型名称、版本、生成配置、规则版本、输入哈希和产物哈希需要记录。更换初稿模型或其规则版本，保留旧稿。批量生成工具与预算在实施时明确；本次可行性设计没有执行批量推理。

## 5. 人工身份与参考标签怎么保存

保留三层，内容不互相覆盖：

1. **冻结原材料/原答案**：只读。
2. **AI 草稿与解释提案**：`review_kind=ai_note`，没有 human 的确认权限。
3. **人工最终记录**：明确确认后创建，通常为 `review_kind=human_with_ai`，记录 reviewer、所见草稿版本、所采纳证据和最终字段。

在人工确认时计算 `adopted_unchanged / adopted_modified`。`human_authored` 仅说明该条从空白开始填写，不证明没见过 AI；看过 AI 时审核类型仍为 `human_with_ai`。自动保存、打开页面、AI 已填满字段及“没有改动”都不代表确认。

“与原答案相同/不同”由程序直接比较，但 `accepted / suspected_error / policy_ambiguous / context_insufficient` 需要人确认其语义。示例可靠性可按已确认的原答案审核状态确定性映射：认可→支持，同口径疑错且有明确裁决→不支持，规则/语境未解决→未能判断；没有裁决的疑点不能自动映射为不支持。

`confirmed` 表示人完成了一条记录；`resolved` 表示该任务有可用硬参考；`null` 仍表示未决。比较离散预测时只使用对应任务已解决的裁决；同一 case 的两个任务分别计数。

复用记录必须绑定具体版本。共享示例、词典定义或 policy 发生语义更改时，标记受影响的下游关系/资格需重核，保留原快照，不默默替换已经确认的关联。后续人可以修改 AI 漏掉的条目，但不能用删除行来掩盖未审。

## 6. 用 3169 看精简后的实际操作

下面只沿用已有[案例材料](../../../exps/causal_context/general_model_ld_nolabel_paired_cases_v1/results/paired-cases-02/cases/card_data/07-3169.json)和此前对话演示，展示交互效果；已知有结果暴露，**不是新生成的独立初稿或正式审核记录**。

| 页面预填内容 | 人的操作 |
| --- | --- |
| 查询“我想回个嘿嘿嘿嘿。。。感觉好押韵”；hate=非仇恨；group=无任务类别；依据=普通笑声/无攻击命题，附原文高亮 | 判断合理就“确认此项”；不同意则直接改选未决或其他标签，不要求重写解释 |
| 示例 3660：指代/目标待核实；与查询词义关联不明；原答案与 AI 候选并排 | 确认或改选两个任务标签及原答案状态；可靠性自动显示，不重复发问或抄写原答案 |
| 词条“嘿嘿”：定义过窄、对查询错义的疑点；来源显示查询与示例共享 | 核对后采纳或改选；不手写 ID、span 或“删除示例是否仍保留词条” |
| 示例 7611：纯个体冒犯边界，规则歧义 | 选“保持未决—个体冒犯范围”，不重复写一段规范讨论 |
| 其余示例及义项 | 用相同表格逐项核对；已确认的全局审核直接引用，当前查询关系仍确认 |
| 揭示结果后：原标签比较、AI 候选解释及替代解释 | 选择原标注状态和后续用途；解释可暂不采纳，最后“确认并继续” |

若这些预填均能表达人的判断，这一例可以完全不手写。零手写不等于一键完成整例，也不减少必须阅读和确认的材料；所有疑点仍可选择未决。

## 7. 工程可行性与实施范围

现有 [app.js](../../../tools/general_model_paired_review_ui/app.js) 已有 choice buttons、三栏组件和自动保存；[store.py](../../../tools/general_model_paired_review_ui/store.py) 与 [server.py](../../../tools/general_model_paired_review_ui/server.py) 已提供文件锁、revision、快照、阶段 API 和导出。可以复用这些组件。

但旧 store 的 `normalize_notes` 只接受固定文本字段，`require_resources / require_assessment` 强制手写内容，`reveal_ai` 又要求先完成人工初判。**需要新增 evidence 模式和独立 schema，同时改前后端校验与开放顺序；只把 textarea 换成下拉框不够。** 旧会话只读衔接，新模式独立存储，部署另行实施。

实现重点是：结构化字段及合法组合、AI 原稿与人工确认分层、阶段输入白名单、重复资源版本引用、选择后证据同步、逐项/显式批量确认，以及冲突恢复。沿用 32 discovery，不把 16 reserve 用于界面调试或规则选择。

验证使用隔离会话覆盖：AI 导入不会增加人审完成数；未决与空集合可区分；没有材料快照不能取轨迹；批量确认不包含未指定行；共享记录更正会提示受影响引用；保存失败/冲突保留本地草稿；重启能续审，手机可读全文。自动测试记录不能计入正式审核。

可先在 discovery 既有顺序的小批材料上试用，记录实际手写字符数、展开/修改次数、活跃审核耗时和未决原因。若没有独立不看 AI 的对照，只能评估可用性与工作量，不能宣称测出了 AI 带来的准确率或因果提效。现阶段不另加全队列双人重审或强制第二轮盲审；需要独立标注一致性时再设独立设计。
